# wenay-examples

Каталог небольших законченных SaaS на **wenay-common2** и **wenay-react2**. Каждый пример — рабочий продукт с ролями, хранением, проверками и понятным путём масштабирования, пригодный как основа нового проекта.

Репозиторий решает две задачи сразу: даёт основу для быстрого старта и на реальных сценариях выясняет, каких возможностей не хватает библиотекам.

## Быстрый старт

```text
cd apps/support
npm ci
npm test
npm run build
npm start
```

Каждое приложение запускается самостоятельно и не требует соседних. Порт и каталог данных меняются переменными `SERVICE_PORT` и `SERVICE_DATA_DIR`.

## Своё приложение из готового

```text
node scripts/create-saas-example.mjs approvals ../my-approvals --name my-approvals --port 4990 --title "Заявки"
cd ../my-approvals && npm ci && npm run typecheck && npm test && npm run build
```

Копируются только исходники, точные npm-зависимости и правила. `--port` и `--title` необязательны: по умолчанию копия получает порт донора плюс 100 и заголовок по имени пакета. Проверки исходного примера переносятся вместе с кодом — каждая помечена в первой строке как унаследованная, а `SCAFFOLD.md` в копии перечисляет их и говорит, что менять первым. Что менять дальше — [рецепты для разработчика и ИИ](doc/SAAS-RECIPES.md).

## Проверка всего каталога

```text
npm run check:all
```

Последовательно прогоняет typecheck, тесты и сборку всех приложений, включая оба UI пиццерии,
проверяет копировщик, достоверность логов, синхронность, стиль и ссылки. CI пропускает test hosting,
но проверяет его типы и сборку. Live Docker-проверки запускаются отдельно. После обновления версий
или изменения исходов выполните `npm run status`: логи привязаны к package.json и lock,
а проверка STATUS только сверяет документы. Отдельные этапы: `check:apps`, `check:repo`.
