# Daylight — запись и расписание

<!-- status:versions -->
Текущие зависимости: **common2 3.1.1 / react2 5.0.0**.
<!-- /status:versions -->

Самостоятельный пример бронирования: ресурсы и услуги, доступность по зонам IANA, временные удержания, подтверждение и перенос, лист ожидания, локальные напоминания и тестовый депозит. Authority принимает все изменения вместимости, обслуживающие узлы отдают ролевые проекции. Своего транспорта, Zod и самописного планировщика таймеров нет.

## Интерфейс примера

Первый экран объясняет путь записи: выбор услуги и времени → удержание места → подтверждение.
В календаре отдельно показаны загрузка, ошибка запроса и отсутствие активных услуг. При потере
связи появляется уведомление, а операции с записью остаются недоступны до подключения.
Подписи календаря и статусов увеличены, выбранное время выделено; на узком экране неделя
прокручивается внутри календаря, а услуги расположены над ним.

Рабочий экран организован в три шага: услуги сверху, календарь и постоянная карточка выбранной
встречи рядом. До выбора времени карточка показывает услугу, длительность, место и число участников;
после выбора — условия записи. Число свободных вариантов относится к текущему запросу календаря,
а кнопка перехода к подтверждению показывает фактическое число удержанных записей.

Браузерный сценарий для приёмки: клиент удерживает время, подтверждает встречу, переносит её
и проверяет историю; сотрудник просматривает встречи команды. Отдельно проверить пустой список
услуг, ошибку календаря, смену услуги и обновление сводки выбора, клавиатуру и экран 390 px.
Успешная сборка не заменяет эту приёмку.

## Запуск

```text
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:3814. Данные — в `booking-data`; порт, адрес и каталог меняют `SERVICE_PORT`, `SERVICE_HOST` и `SERVICE_DATA_DIR`, отдельно задаются стабильные `SERVICE_TOKEN_SECRET` и `SERVICE_NODE_TOKEN`. `BOOKING_HOLD_MS` задаёт TTL удержания (по умолчанию 300000, максимум 900000); малые значения нужны автоматическим проверкам. `.env` автоматически не загружается. Для разработки — `npm run dev` с прокси к 3814.

## Роли и демоданные

| Аккаунт | Пароль | Роль |
| --- | --- | --- |
| owner | owner-pass | Все настройки и брони Northstar Studio |
| staff | staff-pass | Исполнитель: свои ресурсы и услуги, календарь и брони организации |
| customer | customer-pass | Только свои брони, ожидание и напоминания |
| customer2 | customer2-pass | Второй независимый клиент для проверки последнего места |
| outsider | outsider-pass | Владелец Harbor Labs, без доступа к Northstar |

Northstar: ресурс `studio`, зона Europe/Berlin, вместимость 2, понедельник–пятница 09:00–18:00. Услуга `consultation` — 45 минут встречи и 15 минут после, один участник на бронь. Один ресурс обслуживает несколько услуг, но их брони делят общую вместимость.

Сценарий: клиент открывает календарь и получает снимок доступности → создаёт удержание на пять минут → подтверждает его, пройдя повторную проверку TTL, ревизии и тестового депозита → переносит бронь, и при конфликте исходная запись остаётся прежней → занятое время можно занять из листа ожидания, когда место освободится → за час до начала появляется локальное напоминание.

`bookingReschedule` переносит будущую подтверждённую бронь на другую активную услугу своей организации,
в том числе на другой ресурс. Клиент меняет только свою бронь; сотрудник и владелец — любую бронь
доступной организации. Новая услуга должна совпадать с сохранённой длительностью встречи и размером
депозита. Состояние оплаты сохраняется, буферы и зона берутся у цели; конфликт не меняет исходную
бронь. Прежний `bookingMove` продолжает менять время текущей услуги по её актуальной конфигурации.

## Графическое расписание

Календарь по умолчанию открывает день со всеми ресурсами; доступна неделя
с колонками «день × ресурс» и вертикальной шкалой времени. Фильтр ресурса сужает сетку;
при смене зоны или исчезновении выбранного ресурса он сбрасывается на все доступные ресурсы.
Карточка занимает фактический интервал встречи; пересекающиеся встречи делят ширину колонки.
Ресурсы разных часовых поясов показываются отдельно: выберите IANA-зону в панели.
Начальная прокрутка открывает первую встречу или начало рабочего дня; масштаб можно изменить,
сохранив видимое время. Заголовки дней остаются закреплёнными при прокрутке.

Выберите будущую подтверждённую встречу. После проверки доступности зелёные отметки показывают
возможные начала. Перетащите ручку ⠿ на свободное время или совместимый ресурс: пунктирная
карточка показывает предпросмотр. Отпускание ручки ещё не меняет запись — нажмите
«Подтвердить перенос» в панели встречи. Отмена предпросмотра сохраняет исходное время.
С клавиатуры: фокус на ручке, Space — начать, ↑↓ — следующий/предыдущий свободный слот,
←→ — соседний видимый совместимый ресурс, Shift со стрелкой — четыре шага,
Space или Enter — закончить предпросмотр, Escape — отменить.
Выбор услуги/ресурса и свободного времени в панели работает без перетаскивания.

Сотрудник выбирает совместимую активную услугу своей организации; клиент в этом интерфейсе
меняет только время своей услуги. Сохранённая длительность и размер предоплаты показаны
в панели и должны совпадать с целевой услугой. Изменившиеся условия услуги не подменяют
условия существующей встречи. Удержания и уже начавшиеся встречи доступны для просмотра;
история остаётся в разделе встреч.
Изменение записи, каталога, роли, периода или соединения отменяет устаревший предпросмотр.

Для новой записи раскройте «Записаться: выбрать услугу и свободное время» под расписанием.
Существующие подбор услуги, свободные слоты, помощник, удержание и лист ожидания сохранены.
Клиент видит только свои встречи; чужие карточки и заметки не входят в его workspace.
Пустая колонка означает отсутствие видимых встреч, а не гарантию свободной вместимости.
На днях перехода DST шкала содержит реальные 23/25 часов (в других зонах возможны дробные
переходы); повторившийся час подписан UTC-смещением, а несуществующее время не предлагается.

## Границы

- Доступность — снимок, а не разрешение записаться: создание удержания повторяет все проверки внутри команды authority.
- Несуществующее местное время в переходе DST не превращается в предложенный слот; повторившийся час даёт два момента с разным смещением, и интерфейс обязан его показывать.
- Один authority остаётся транзакционным владельцем вместимости. Несколько обслуживающих узлов — масштабирование чтений и соединений, а не несколько независимых авторов.
- Напоминания локальные: запись появляется в `notices`, письма, SMS, push и сторонние аккаунты не вызываются.
- `depositSimulate` моделирует событие оплаты и не является webhook настоящего провайдера: эквайринга и возвратов нет, успешный тестовый депозит сам по себе бронь не подтверждает.
- Помощник разбирает пожелания явно подписанным тестовым разборщиком без языковой модели и **не имеет команд изменения броней**: применить предложение — отдельное действие человека.
- Пределы стенда: 50 ресурсов, 100 услуг, 2000 броней, 500 заявок ожидания, 4000 ключей намерений, 2000 записей аудита; доступность — 1–14 дней, горизонт 180 дней, 1000 слотов в ответе.
- Нет синхронизации iCal и Google, внешней регистрации клиентов, массовых рассылок и очистки семантических ключей.

## Проверки

```text
npm run typecheck
npm test
npm run build
```

`npm test` проходит домен через настоящий service leader, локальные проверки помощника и сетевой тест с authority и двумя обслуживающими узлами. Домен: весенний разрыв и осеннее повторение, 30-минутный переход Lord Howe, исключения расписания, буферы, ограничение диапазона, роли, отсутствие утечки чужих броней, гонка за последнее место, TTL, перенос с конфликтом, предложение из листа ожидания, напоминания, поздний тестовый депозит. Сеть: два реальных клиента, отключение узла, стабильный store, автоматическое истечение удержания, перезапуск authority и восстановление брони с ключом намерения. Docker для этого не нужен.

`npm run test:assistant` отдельно проверяет отсутствие автоматической записи, недоступность чужой организации, изменение доступности после предложения, отмену, тайм-аут, поздний ответ, отзыв роли и восстановление частного результата. Холодная копия — `npm run test:backup`. Размещение — `npm run test:booking` из `apps/hosting`: first, second и откат с сохранённым удержанием, подтверждением и напоминанием, контейнер 256 МиБ.

Атомарный перенос и ACL проверяются отдельно от браузерных жестов: `backend/reschedule-check.ts`
проходит совместимость условий, конфликты, исключение текущей брони из доступности,
дедупликацию и сохранение исходной записи при отказе. Проверка типов не подтверждает
положение карточек или работу указателя. Для графического UI нужны отдельные проходы
мышью и клавиатурой: предпросмотр/подтверждение, Escape, прокрутка во время переноса,
изменение revision и потеря соединения. Физическое сенсорное устройство пока не проверено.
