# Витрина примеров

Запуск из корня: `node apps/catalog/server.mjs`, затем http://127.0.0.1:3800/.
Из каталога приложения: `npm start`. Порт задаётся `CATALOG_PORT`.
Сервер слушает только loopback, отдаёт явно разрешённые файлы и README.
Он не запускает приложения, не управляет Docker и не хранит данные.

## Выбор и запуск

Витрина охватывает 11 приложений; органайзер описан внутри примера пиццерии.
Карточки объясняют бизнес-задачу и этапы процесса. Поиск работает по названию,
описанию и ролям, без учёта регистра и различия е/ё. Категория, поиск и фильтр
успешных прогонов применяются вместе; пустая выдача предлагает сбросить фильтры.

Кнопка «Сценарий и запуск» открывает роли, команды локального запуска и README
с аккаунтами. Ссылка на приложение явно требует предварительного запуска сервера.
Команды можно скопировать; при отказе Clipboard API показан способ ручного копирования.
Escape закрывает окно и возвращает фокус на открывшую кнопку.

Карточки не изображают интерфейсы и не содержат вымышленных рабочих показателей.
Верхний блок описывает процесс поддержки. Настоящие снимки интерфейсов пока
не включены в каталог; существующие маршруты `/screenshots/<id>.png` сохранены.

## Результаты проверок

`products.js` генерирует `scripts/catalog.mjs` из `presentation.json`,
паспортов и результатов того же сборщика, который формирует `doc/STATUS.md`.
Данные включают время последней записи (UTC), результаты typecheck/test/build
и наличие scaffold. Править сгенерированный файл вручную нельзя: `npm run status`
из корня обновляет его вместе со STATUS.

«Успешный прогон записан» означает сохранённые успешные результаты для текущих
package.json и lock. Это не проверка доступности сервера и не подтверждение
свежести исходников. В подробностях показаны отдельные результаты, пропуски,
ограничения и предупреждение повторить проверки после изменений.

Самостоятельная копия предлагается только при наличии scaffold.json.
Её адрес отличается от исходного приложения: используйте README созданной копии.
Hosting требует подготовленного окружения; интерфейс не обещает подготовку
произвольного сервера. Органайзер запускается через `npm run start:organizer`
из apps/pizzeria после установки зависимостей и сборки.

## Реализация и проверка

HTML/CSS/JavaScript без runtime-зависимостей; TypeScript проверяет JS через checkJs.
Сами продуктовые приложения используют опубликованные wenay-common2/react2.
Витрина сохраняет небольшую статическую реализацию без нового транспорта или UI-фреймворка.

`npm run typecheck` и `npm test` проверяют типы, полноту каталога, соответствие
портов/результатов/дат STATUS, категории, поиск и сочетание фильтров, отсутствие
ложной готовности и доступность команд создания копии.

Браузерная приёмка: desktop и узкий экран, поиск, категории, пустая выдача/сброс,
клавиатура и фокус диалога, копирование команд, чтение README. Результаты общей
переработки фиксируются в doc/changes в корне репозитория.
