# Витрина примеров

Запуск: `npm start` из этого каталога (или `node apps/catalog/server.mjs` из корня), затем http://127.0.0.1:3800/. Порт задаётся `CATALOG_PORT`. Node без дополнительных зависимостей; сервер слушает только loopback и отдаёт явно разрешённые файлы. Не запускает другие приложения, не управляет Docker, не хранит данные.

Статическая витрина описывает сценарии, роли, команды самостоятельной копии и ограничения. Продукты открываются в отдельной вкладке; до этого их нужно запустить по своим README. Это обычный HTML-каталог, а сами приложения используют опубликованные common2/react2.

Карточка всегда показывает **подписанную схему сценария**, а не снимок экрана: `catalog.js` рисует её сам, и она не выдаётся за интерфейс. Настоящих снимков в витрине пока нет.

Сервер уже умеет отдавать `/screenshots/<id>.png` из `doc/screenshots/`, но карточка их не запрашивает: чтобы витрина показывала настоящий интерфейс, нужно и положить файлы, и научить `visualOf` в `catalog.js` показывать изображение вместо схемы. Прежняя фраза про `screenshot: true` в записи продукта описывала несуществующий флаг — такого поля нет ни в `presentation.json`, ни в генераторе. Метаданные карточек обновляются вместе со столбцом «Статус» в `doc/SAAS-EXAMPLES-BACKLOG.md`. Будущие продукты видны только в фильтре «Все примеры».

`products.js` генерируется `scripts/catalog.mjs` из авторского оформления `presentation.json`, паспортов приложений и `doc/STATUS.md`. Флаг готовности карточки — результат реальных проверок, а не ручная отметка: править его напрямую нельзя, запустите `npm run status` из корня.

## Скелет и зависимости

Витрина следует общему скелету каталога: `package.json` со скриптами `start`, `typecheck` и `test`, `tsconfig.json`, собственная проверка. Но **в рантайме зависимостей нет**: сервер и клиент — обычный JavaScript, страница открывается без установки чего-либо. TypeScript подключён только как инструмент разработки и проверяет эти же файлы через `checkJs`.

`npm test` (`check.mjs`) сверяет карточки с `doc/STATUS.md`: порт каждой карточки совпадает с портом приложения, флаг готовности — с фактическим результатом проверок, разметка паспорта не просочилась в текст, а сам `products.js` собран генератором, а не правился руками.
