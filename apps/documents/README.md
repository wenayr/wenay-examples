# Papertrail — студия обработки документов

<!-- status:versions -->
Текущие зависимости: **common2 3.1.1 / react2 5.0.0**.
<!-- /status:versions -->

Самостоятельный пример: загрузить CSV, UTF-8 TXT или текстовый PDF, извлечь строки, проверить рядом с источником, исправить ячейки, утвердить и выгрузить CSV/JSON. Для запуска не нужны поддержка, пиццерия, Docker или платный ИИ.

## Запуск

Требуется Node.js 22.13+ или 24+. Из этого каталога:

```text
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:3811. Для разработки `npm run dev` поднимает интерфейс с прокси к backend. Данные — в `documents-data`; порт и каталог меняют `SERVICE_PORT` и `SERVICE_DATA_DIR`. Для Python-обработчика задайте `DOCUMENT_PYTHON` — абсолютный путь к Python 3; иначе берётся `python` из PATH. Пакеты Python не требуются.

## Роли и демоданные

| Аккаунт | Пароль | Доступ |
| --- | --- | --- |
| `owner` | `owner-pass` | Владелец Northstar: документы, проверка и права участников |
| `reviewer` | `reviewer-pass` | Проверка и утверждение документов Northstar |
| `customer` | `customer-pass` | Загрузка, просмотр и экспорт собственных документов Northstar |
| `outsider` | `outsider-pass` | Владелец другой организации Harbor, без доступа к Northstar |

Аккаунты демонстрационные: производственный проект заменяет локальную идентификацию своим источником пользователей, роли организации и проверки предметных команд остаются явными.

Сценарий: клиент загружает CSV и запускает Node-обработчик → проверяющий сверяет источник с таблицей, правит ячейку и добавляет комментарий → утверждает версию, клиент скачивает CSV или JSON → документ возвращают на проверку, прежняя утверждённая копия остаётся неизменной → CSV с кавычками и переносами повторно обрабатывается настоящим процессом Python → PDF с текстовым слоем разбирается по страницам, а скан без текста отклоняется с объяснением.

Один файл — один документ. Повторная загрузка тех же байтов с тем же именем тем же пользователем не создаёт дубликат; после удаления загрузка начинает новую `sourceVersion` и увеличивает ревизию.

Сравнение версий по умолчанию показывает последнюю утверждённую копию, а после нового утверждения — предыдущую.
Другую копию можно выбрать вручную; при открытии другого документа выбор сбрасывается. Если таблицы совпадают,
экран объясняет отсутствие изменений вместо повторения одинаковых ячеек.

Браузерная приёмка 26 сентября 2026 на отдельном архиве: загрузка примера, извлечение,
первое утверждение v4, исправление цены 45000→46000 и новое утверждение v7.
Сравнение автоматически выбрало v4; ручной выбор v7 показал отсутствие различий.

## Границы

- 512 КиБ на файл; до 50 записей документов вместе с удалёнными и 50 сохранённых запусков. До 200 строк, 20 колонок, 1000 символов в ячейке, 512 КиБ извлечённой таблицы, 50 комментариев и 5 утверждённых версий.
- Одновременно принимаются две обработки разных документов; третья получает отказ до освобождения места. Планировщика большой очереди здесь нет.
- PDF: до 10 страниц и 200 000 символов, только текстовый слой. OCR, сложная табличная вёрстка, изображения и зашифрованные файлы не поддерживаются. Парсер — опубликованный `pdfjs-dist@6.3.289`, публичные API из [Node-примера Mozilla](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs).
- PDF исполняется отдельным процессом с пределом V8 heap 256 МиБ; это не весь RSS. Общий тайм-аут задания — 10 секунд.
- Python получает путь к приватному временному CSV и возвращает ограниченный JSON через stdout: текст файла не попадает в аргументы оболочки, временный файл удаляется.
- Экспорт CSV экранирует кавычки и защищает значения, которые табличная программа приняла бы за формулу; JSON сохраняет точные значения.
- Запись принадлежит одному authority, обслуживающие узлы проксируют файловый ресурс к нему. Общего файлового доступа и переключения владельца хранилища нет.
- Обработчик заменяется через `DocumentProcessor.extract` и порт `ExtractionProvider`; по умолчанию работает детерминированный локальный fixture — **не OCR и не языковая модель**. Платных вызовов нет.
- После рестарта незавершённый документ получает состояние `uncertain`: автоматического повтора обработки нет, разрешена новая явная попытка.

## Проверки

```text
npm run typecheck
npm test
npm run test:machine
npm run build
```

`npm test` проверяет кавычки и переносы CSV, UTF-8 TXT, настоящий текстовый PDF, отсутствие текстового слоя, защиту паролем, повреждение и лимит страниц, права организаций, внутренние команды, размер, дедупликацию, конкурирующие правки, неизменность утверждения, экспорт, два одновременных задания, отмену, поздний ответ, повтор, тайм-аут, отзыв прав, физическую очистку, повторную загрузку и продуктовый HTTP-фасад. Если `DOCUMENT_PYTHON` не задан, шаг с настоящим Python явно отмечается пропущенным.

`npm run test:advanced` требует заданный `DOCUMENT_PYTHON`: одновременные живые Node- и Python-процессы, отмена одного без вреда другому, поздний результат отменённой попытки. Холодная копия и восстановление — `npm run test:backup`. Размещение — `npm run test:documents` из `apps/hosting`: Node CSV, Python CSV и PDF в контейнере 256 МиБ, обновление и откат.

Для автоматизации owner выпускает ключ организации через native `productKeys.control.issue` с единственным scope `documents:extract`. Машинный login использует `product:<id>` и однократно выданный secret; сервис хранит только hash и не добавляет ключ в human members. После native login доступен только `productDocuments` с upload/start/status/result либо одноимённые четыре HTTP-метода. Ключи разных организаций и разные ключи одной организации изолированы. Отзыв/истечение прерывает задание; закрытие HTTP/RPC запроса сохраняет принятый durable run. Полный контракт, retry и recovery — в [API.md](API.md).
