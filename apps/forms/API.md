# Petal — устройство и контракт

Справочник к [README](README.md): описание формы и публикация, публичный фасад приёма ответов, агрегаты с исправлением и хранением, выгрузка и группировка текстовых ответов.

## Форма и публикация

`formSave` принимает `{orgId, id, revision, title, description, fields, retentionDays}`; новая форма использует `id: ''`, `revision: 0`. Каждый элемент `fields`:

```ts
{
    id: 'details', label: 'Что улучшить?', kind: 'longtext', required: true,
    choices: [], min: 1, max: 2000, whenField: 'recommend', whenEquals: 'false'
}
```

Типы: `text`, `longtext`, `number`, `choice`, `boolean`. Для чисел `min/max` задают диапазон, для текста — длину. Условие ссылается на поле `choice` или `boolean`; без условия обе строки пустые. Редактор проверяет отсутствующие ссылки и циклы. Порядок массива — порядок отображения. Перестановка не меняет идентичность поля.

В SC1-ресурсе `editor`:

- `control.detail({orgId, id})` возвращает черновик и опубликованные версии без хеша токена.
- `control.publish({orgId, id, revision, requestId})` создаёт неизменяемую версию и выдаёт `{id, version, token}`. `token` показывается только в первом ответе. Повтор того же запроса возвращает `token: null`; конфликт параметров отклоняется. При потере ответа выпустите новую публикацию.

Публикация сохраняет только SHA-256 случайного токена. Черновик не меняет уже опубликованный текст или диапазоны. Каждая новая публикация выдаёт новое поколение доступа; `formDisable` закрывает ссылку. Principal респондента связан с формой **и поколением**: старая сессия не оживает после повторной публикации.

Публичный URL содержит токен в fragment `/#respond=...`: fragment не отправляется HTTP-серверу и не должен сохраняться в аналитике. Клиент хранит сессии сотрудника и респондента отдельно. Сервер задаёт `Referrer-Policy: no-referrer`. По умолчанию страницы разрешено встраивать только на том же origin. `FORM_FRAME_ANCESTORS` позволяет оператору указать точные HTTP(S) origins через запятую; произвольные origins из определения формы не принимаются. Авторизация API и CORS остаются библиотечными механизмами. Произвольные HTML/script поля не поддерживаются.

## Публичный фасад и проверка ответов

После стандартного входа респондент открывает `publicform`:

```ts
const published = await publicform.control.current()
const receipt = await publicform.control.submit({
    version: published.version,
    nonce: crypto.randomUUID(),
    answers: {rating: 4, recommend: false, details: 'Нужен более быстрый поиск'}
})
```

Фасад показывает только текущую опубликованную форму и принимает ответ. Он не читает чужие или предыдущие ответы и не меняет редакторские настройки.

Схема активных полей собирается в публичный `tInputSchema`. Опубликованный `buildInputValidate` проверяет типы, enum, обязательность и неизвестные поля. Условия, диапазоны, длина и общий размер — предметные правила примера. Ответ на скрытое поле отклоняется, а не молча сохраняется. Нет Zod или нового HTTP/RPC транспорта.

`nonce` обозначает одну отправку. Повтор с теми же данными не удваивает запись и агрегаты, даже после рестарта. Другое содержимое с тем же nonce отклоняется. После удаления запись не восстанавливается повтором: остаётся небольшой tombstone без содержимого/его хеша. Внутри ресурса новая попытка получает новый command requestId, сохраняя nonce; так предметная проверка выполняется и при повторе пользователя. Повтор одного библиотечного requestId по-прежнему возвращает исходный receipt.

Опубликованная версия проверяется при приёме; старую открытую форму после перепубликации нужно перезагрузить. Сеть не может подменить tenant: он берётся из principal опубликованной формы. Библиотечный лимит `answerSubmit` — 30 команд в минуту на principal формы/поколения, общий — 120. Это ограничение всего публичного потока формы; CAPTCHA и индивидуальная идентификация респондентов здесь не реализованы.

## Агрегаты, исправления и хранение

Общая подписка содержит только метаданные и агрегаты по версии: число ответов, заполненность каждого поля, сумму/среднее чисел и счётчики вариантов выбора/да-нет. Свободный текст в неё не входит. При добавлении, исправлении и удалении меняется соответствующий агрегат; клиенту не пересылается весь массив исходных ответов для пересчёта.

`answers.control.list({orgId, formId, version, offset, limit})` возвращает до 100 разрешённых записей и `answersRevision`; `version: 0` означает все версии. Владелец вызывает `answerCorrect({orgId, formId, id, answersRevision, answersJson})` или `answerDelete({orgId, formId, id})`. Исправление проходит проверку исходной опубликованной схемы, удаление и исправление обновляют агрегаты в той же доменной команде.

Срок хранения — 1–365 дней, фиксируется для ответа при приёме. Изменение настройки влияет на последующие ответы. Просроченные записи сразу исключаются из новых частных чтений. `createReconciler` и `ctx.retry` планируют ближайшую очистку; системная команда одновременно удаляет текущий ответ, очищает его fingerprint и уменьшает агрегаты. Счётчики сходятся после этой команды.

После исправления/удаления сервер берёт текущий keyframe и вызывает публичный `openFsReplayStorage.compact()`: старый текст удаляется также из активного дискового журнала. Это выполняется только при изменениях, требующих удаления данных, и при старте после возможного прерывания очистки. Приём каждого обычного ответа не переписывает весь архив. Этот механизм не стирает ранее снятые резервные копии, чужие выгрузки, историю файловой системы или память внешнего клиента; для них нужна отдельная политика хранения.

## Выгрузка

SC1-ресурс `exports` использует `createAiRunHost` как долговечное задание без ИИ-вызова:

```ts
const run = await exports.ai.createRun({
    requestId: crypto.randomUUID(), kind: 'export', resourceIds: [formId],
    input: {orgId, formId, revision: answersRevision, version: 0, format: 'csv'}
})
```

После состояния `completed`, `exports.control.result(run.id)` выдаёт `{name, mime, bytes}`. Строки обрабатываются страницами по 100, максимальный файл — 2 MiB, CSV экранирует потенциальные формулы. Результат хранится через `createLocalBlobStorage`. В AI replay содержится только флаг готовности, без ответов и bytes.

Отмена до сохранения файла не публикует результат. Выгрузка привязана к автору и `answersRevision`: добавление, исправление, удаление или истечение ответа делает старый файл недоступным. Очистка удаляет устаревший файл с диска; хеши одинаковых файлов могут разделяться, пока остаётся действующая ссылка. Отзыв роли проверяется на каждом чтении. Прерванное рестартом задание не запускается повторно автоматически, а завершённый частный файл восстанавливается.

## Группировка текстовых ответов

Ресурс `grouping` использует опубликованный `createAiRunHost`: запуск, отмена, восстановление состояния и прогресс остаются библиотечными. Встроенный исполнитель — **детерминированное демо по ключевым словам**, без платного запроса, модели, оценки точности или статистической достоверности. Он распределяет ответы по темам «Цена», «Скорость», «Удобство», «Другие ответы». Порт `GroupingProvider` позволяет отдельно подключить и проверить настоящий исполнитель.

```ts
const run = await grouping.ai.createRun({
    requestId: crypto.randomUUID(), kind: 'group', resourceIds: [formId],
    input: {orgId, formId, version, answersRevision, fieldId: 'details'}
})
// После completed:
const result = await grouping.control.result(run.id)
```

Нужны 3–200 непустых ответов текстового поля одной опубликованной версии. Меньшая выборка отклоняется, большая требует отдельного решения по выборке; скрытой обрезки нет. Результат содержит `groups: [{label, sourceIds}]`, размер выборки, `revision` и признак `demo`. Каждый текущий источник входит ровно в одну группу. Ответы не дописываются и не исправляются автоматически.

Создавший результат владелец/автор может вызвать `control.correct({runId, revision, groups})`: до 20 групп, уникальные названия до 100 символов, все исходные идентификаторы без пропусков/повторов. Аналитик создаёт и читает собственный результат, но не меняет его. Ошибка версии защищает одновременное ручное исправление.

Текст ответов и названия групп отсутствуют в AI replay: там только состояние и флаг готовности. Частный журнал результата доступен через текущие права владельца запуска, версию исходных ответов и срок хранения. Добавление/исправление/удаление ответа или отзыв роли закрывает старый результат; очистка удаляет его из активного частного журнала. Retention-очистка делает то же для истёкших источников; новый запрос результата проверяет срок сразу. Прерванные перезапуском задания завершаются ошибкой, без автоматического повторного вызова исполнителя. Отмена, таймаут и изменение исходных данных не публикуют запоздалый ответ.
