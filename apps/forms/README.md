# Petal — формы и обратная связь

<!-- status:versions -->
Текущие зависимости: **common2 2.21.1 / react2 3.5.1**.
<!-- /status:versions -->

Самостоятельный пример динамических форм: редактор вопросов с условиями, неизменяемые публикации, отдельный доступ респондента по ссылке или в iframe, приём ответов, инкрементальные агрегаты, исправление и удаление, срок хранения, выгрузка и группировка текстовых ответов.

## Запуск

```text
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:3815. Данные — в `forms-data`; порт и каталог меняют `SERVICE_PORT` и `SERVICE_DATA_DIR`. Описание клиента публикуется по `/api/client`, библиотечные login и команды — под `/api/forms`, документация — `/docs` и `/openapi.json`. Для разработки — `npm run dev`.

`FORM_FRAME_ANCESTORS` перечисляет через запятую точные origin, которым разрешено встраивать публичные страницы; по умолчанию это только собственный origin.

## Роли и демоданные

| Аккаунт | Пароль | Роль |
| --- | --- | --- |
| `owner` | `owner-pass` | Состав команды Northstar, исправление и удаление ответов |
| `author` | `author-pass` | Редактирование и публикация форм |
| `analyst` | `analyst-pass` | Чтение форм, агрегатов, ответов и выгрузок |
| `outsider` | `outsider-pass` | Владелец Harbor без доступа к Northstar |

Респондент сотрудником не является и административного представления не получает: он входит стандартным login с `account: 'respondent'` и публичным токеном формы. Универсального демо-пароля у него нет. Последнего владельца удалить нельзя.

Сценарий: автор собирает форму с условными вопросами → публикует неизменяемую версию и один раз получает публичный токен → респондент открывает ссылку `/#respond=...` и отправляет ответ с `nonce` → агрегаты меняются той же командой, свободный текст в общую подписку не попадает → владелец исправляет или удаляет ответ, и текст исчезает в том числе из активного журнала → аналитик выгружает CSV или JSON и группирует открытые ответы по темам.

## Границы

- Публичный токен показывается только в первом ответе публикации и хранится как SHA-256. Потерянный ответ закрывается новой публикацией.
- Сессия респондента связана с формой **и поколением**: после повторной публикации старая ссылка не оживает, `formDisable` закрывает доступ.
- Токен передаётся во fragment URL: он не уходит на сервер и не должен попадать в аналитику. Произвольные HTML и script в полях не поддерживаются.
- Повтор `nonce` с теми же данными не удваивает запись и агрегаты даже после рестарта; после удаления остаётся tombstone без содержимого, и повтор запись не восстанавливает.
- Группировка открытых ответов — **детерминированное демо по ключевым словам**, без модели, платных запросов и статистической достоверности; порт `GroupingProvider` позволяет подключить настоящий исполнитель.
- Выгрузка привязана к автору и `answersRevision`: любое изменение ответов делает старый файл недоступным, устаревший файл удаляется с диска.
- Пределы стенда: 100 форм, 20 полей и 20 версий на форму, 20 вариантов выбора, 200 символов текста и 2000 длинного текста, 32 KiB на ответ, 5000 ключей приёма вместе с tombstones, 20 заданий выгрузки и 50 группировки. Срок хранения — 1–365 дней, фиксируется при приёме.
- Частота публичного потока ограничена библиотекой: 30 команд приёма в минуту на principal формы и поколения. CAPTCHA и идентификации респондентов нет.
- Компактизация журнала удаляет текст из активного архива, но не из снятых ранее резервных копий, чужих выгрузок и памяти внешнего клиента — для них нужна своя политика хранения.

## Проверки

```text
npm run typecheck
npm test
npm run build
```

`npm test` проходит настоящий service leader и сетевой SC1: динамическая проверка ответов и граф условий, скрытые, неизвестные и обязательные поля, версии и отзыв публичного поколения, семантические повторы, инкрементальные агрегаты, исправление, удаление и срок хранения, приватные страницы, точные байты CSV и JSON, отмена до сохранения, восстановление после перезапуска, исчезновение удалённого текста из активного журнала и отзыв роли на открытом ресурсе. Отдельно проверяются фасад группировки (минимальная выборка, источники версии, чужая организация, ручные исправления, конфликт версии, отмена, тайм-аут, поздний ответ) и authority с двумя обслуживающими процессами: 20 параллельных ответов через двух клиентов, одинаковые агрегаты, остановка узла и полный рестарт.

Холодная копия — `npm run test:backup`. Размещение — `npm run test:forms` из `apps/hosting`: first, second и откат с сохранённой публикацией, ответами, ручной группировкой и экспортом; отозванные аналитик и публичная ссылка остаются отозванными.
