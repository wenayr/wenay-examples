# Counter — учёт потребления и API-ключи

<!-- status:versions -->
Текущие зависимости: **common2 3.1.1 / react2 5.0.0**.
<!-- /status:versions -->

Самостоятельный пример кабинета API-ключей, потребления и предварительных квот. Единицы и лимиты тестовые: приложение не подключает эквайринг, не списывает деньги и не выдаёт внутреннюю запись журнала за платёжную транзакцию.

## Запуск

Из этого каталога:

```text
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:3812. Данные — в `metering-data`; порт и каталог меняют `SERVICE_PORT` и `SERVICE_DATA_DIR`. Для развития интерфейса — `npm run dev`.

Необязательные server-only настройки тестового провайдера и получателей событий описаны в [`.env.example`](.env.example) и в [справочнике](API.md): без них приложение ведёт учёт, но не принимает события подписки и не разрешает регистрацию исходящих получателей.

## Роли и демоданные

| Аккаунт | Пароль | Доступ |
| --- | --- | --- |
| `owner` | `owner-pass` | Ключи, тестовые лимиты и журнал Northstar |
| `auditor` | `auditor-pass` | Наблюдение за Northstar без изменения ключей и лимитов |
| `outsider` | `outsider-pass` | Владелец Harbor без доступа к Northstar |

Northstar начинает с 1000 единиц в месяц и двумя одновременными резервами, Harbor — со 100 единицами и одним резервом. Это настройки примера, а не коммерческие тарифы.

Сценарий: владелец выпускает ключ с областями `usage:read`/`usage:write` и один раз видит секрет → потребитель обменивает ключ на обычную сессию и резервирует 20 единиц → подтверждает фактические 12, остаток возвращается в квоту → повтор того же `eventId` не удваивает расход → отзыв ключа немедленно закрывает и запись, и чтение.

## Границы

- Единицы, планы и события провайдера — тестовые. Реальных платежей, инвойсов и налогового учёта нет.
- Секрет ключа показывается один раз и хранится как SHA-256 хеш; потерянный первый ответ закрывается отзывом и выпуском нового ключа.
- Период — календарный месяц UTC по серверному времени; клиент не присылает дату. Завершение после границы месяца относится к периоду исходного резерва.
- Квота и резерв меняются атомарно: два конкурентных запроса не могут оба забрать последний остаток. Неизвестный исход внешнего вызова отмечается `usageUncertain`, а не освобождением квоты.
- Пределы стенда: 100 ключей, 5000 событий, 1000 записей аудита, 20 получателей и 1000 доставок; единицы — целые 1–10000. Архивирование не автоматизировано.
- Частота ограничена библиотекой: 120 команд в минуту на principal, изменения лимитов и отзыв ключей — 30. Своего rate limiter нет.
- Доставка webhook повторяема, но не гарантирует ровно один внешний эффект: получатель обязан дедуплицировать по `payload.id`.
- Секрет подписи исходящих событий обязан быть доступен серверу и находится в доверенном состоянии и его копиях — защищайте каталог данных и резервные копии.
- Получатели ограничены server-only allowlist точных origin; credentials в URL, fragments и перенаправления запрещены.

## Проверки

```text
npm run typecheck
npm test
npm run build
```

`npm test` использует настоящий service leader: однократный показ секрета, хешированное хранение, стандартный login, области доступа, чужая организация, конфликт `eventId`, гонка на остатке, параллельные резервы, подтверждение, освобождение и неопределённость, граница UTC-месяца, восстановление журнала, отзыв и истечение срока на уже открытом ресурсе, постраничное чтение. Отдельно поднимаются локальные HTTP-серверы для подписи исходных байтов, сверки версий, дубликатов и перестановок, запаздывающего источника с 503, ограниченных повторов и восстановления прерванной отправки, а также реальная authority с двумя serving nodes, двумя клиентами API и отключением узла.

`npm run test:integration` связывает соседние support и documents и предназначен только для исходного репозитория: в самостоятельную копию он не входит. Холодная копия — `npm run test:backup`. Размещение — `npm run test:metering` из `apps/hosting`: first, second и откат с сохранённым ключом, резервом и журналом, контейнер 256 МиБ.
