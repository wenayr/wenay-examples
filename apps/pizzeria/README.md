## Запуск

Нужен Node.js 22.12+.

```sh
cd apps/pizzeria
npm ci
npm run typecheck
npm test
npm run build
npm start
```

Откройте http://localhost:3500. Для разработки frontend запустите `npm run dev` во втором терминале. Vite проксирует API и Socket.IO на backend.

| Логин | Пароль | Возможности |
| --- | --- | --- |
| alice | alice-pass | Заказ, отмена до приготовления, история |
| chef | chef-pass | Склад, обнаружение порчи, приготовление и готовность своего заказа |
| rider | rider-pass | Забрать заказ и завершить свою доставку |
| manager | manager-pass | Ингредиенты, партии, блюда и рецептуры, кухня, доставка, список аккаунтов |
| owner | owner-pass | Управление, назначение ролей, выручка заведений, число реальных узлов |

Откройте разные браузеры или вкладки для разных ролей: токен хранится в sessionStorage. Новый клиент регистрируется через форму. Заказ проходит Принят → В печи → Готов → В пути → Доставлен. Команды исполняются на сервере; скрытие кнопок не является проверкой разрешений.

Складской сценарий, права и переход со старого архива: [блюда, рецептуры и склад](INVENTORY.md).

[Полная карточка блюда](DISHES.md): описание и состав для клиента, размер порции, фотографии, редактор с предпросмотром и точная рецептура для кухни.

[Органайзер команды](organizer/README.md): доска с перетаскиванием на react2, карточки сотрудников и права, ручные задачи и автоматические задачи из заказов/склада. Встроен в пиццерию; запускается и самостоятельно через `npm run start:organizer` после `npm run build:organizer`.

Встроенная команда загружается при открытии раздела. Во время загрузки виден статус;
при ошибке раздел предлагает обновить страницу, сохраняя навигацию пиццерии.

В пиццерии редакторы органайзера загружаются при открытии «Команда и задачи».
Сводка загрузки сотрудников остаётся доступна на первом экране; ожидание загрузки объявляется через `role=status`.

Проверенные действия от каждой роли и честная оценка объёма приложения: [отчёт об использовании библиотек](../../doc/reports/pizzeria-library-assessment.md). Изменение прав обновляет уже открытый интерфейс сотрудника без повторного входа.

## Хранение и развёртывание

`npm start` сохраняет состояние и receipts в `data/`. `SERVICE_DATA_DIR` задаёт другой абсолютный путь, `SERVICE_PORT` — порт. Один процесс authority на один каталог данных. Не запускайте несколько независимых серверов с общим архивом.

`npm run test:backup` проверяет холодное восстановление составного архива в собственном временном каталоге:
заказ и автоматическую задачу, фотографии, переписку и вложения, завершённое предложение тестового ИИ.
После stop/copy/restore/restart повтор requestId не создаёт второй заказ, сообщение или ИИ-запуск;
проверяются права на восстановленное вложение и отказ при повреждении копии или несовместимом формате.
Проверка входит в `npm test`; это не горячая копия и не приёмка внешнего ИИ.

Для воспроизводимого развёртывания используйте этот checkout и lock-файл: `npm ci`, проверки, сборка, затем `npm start` под менеджером процессов. Сохраняйте каталог данных между релизами. Перед обновлением остановите сервер и скопируйте весь каталог данных; при откате восстановите совместимую пару кода и архива. Для внешнего доступа настройте HTTPS reverse proxy с поддержкой WebSocket и `SERVICE_CORS_ORIGINS=https://ваш-домен`. Закрепите случайные `SERVICE_TOKEN_SECRET` и `SERVICE_NODE_TOKEN` в окружении сервера, чтобы токены не менялись при рестарте. Не сохраняйте секреты в git.

Демо содержит известные пароли и не предназначено для публичной эксплуатации с реальными персональными данными. Онлайн-оплата отсутствует, интерфейс явно указывает оплату при получении. Цены — в евро. HTTP API описан на `/docs`, схема — `/openapi.json`.

## Устройство

- `backend/service.ts` — предметная модель и разрешения приложения.
- `backend/main.ts` — запуск с файловым архивом и статическим frontend.
- `backend/service.ts`, `backend/main.ts` и `backend/serving-node.ts` — композиция предметного фасада; запуск authority и обслуживающих узлов обеспечивается публичным `wenay-common2/service/host`.
- `frontend/main.tsx` — интерфейсы ролей, публичные hooks `wenay-react2/react` и общий адаптер `shared/react/service-session.ts`. Выбор узла, RPC и replay обеспечивает service client common2. HTTP facade доступен для входа и внешних интеграций.
- `organizer/screen.tsx` и `organizer/voice-record.tsx` — захват медиа через `wenay-calls`; `npm run build` собирает также самостоятельный органайзер.
- `npm test` — реальный authority и узел чтения, проверки ролей, изоляции клиентов, повтора requestId и полного цикла доставки.
- `npm run test:network` — независимые заведения, масштабирование, отказы процессов и восстановление архивов.

Библиотеки остаются внешними npm-зависимостями. Исходники соседних локальных репозиториев не участвуют в сборке.

Применение обновлённых библиотек и проверенные ограничения описаны в [изменениях 0.8.0](../../doc/changes/0.8.0.md).
