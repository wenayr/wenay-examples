# Northstar — поддержка команды

<!-- status:versions -->
Текущие зависимости: **common2 3.1.1 / react2 5.0.0**.
<!-- /status:versions -->

Самостоятельный SaaS-пример: организации и приглашения, обращения и закрытые заметки, исполнители и сроки, база знаний с версиями, вложения, уведомления, доска задач и помощник с источниками. Команды, роли, журнал, сессии, репликация, переподключение и ресурсы — из `wenay-common2`; жизненный цикл React-клиентов, подписки и таблицы — из `wenay-react2`. Используются только опубликованные API.

## Интерфейс

Рабочий экран разделяет список обращений, переписку и действия по обращению. Основной текст — 14–15 px,
статусы и подписи — от 12 px. На телефоне список прокручивается горизонтально, а детали расположены под перепиской.
Вход объясняет сценарий поддержки и предлагает демороли. Поиск без результатов позволяет сбросить фильтры;
ошибка подключения и отсутствие доступа показаны отдельно от загрузки. Внешним сервисам посвящён раздел «Ключи интеграций».

Над перепиской расположена рабочая очередь: без первого ответа, с истёкшим сроком, без ответственного и назначенные текущему
сотруднику обращения. Каждая группа открывает соответствующий список. Блок первого ответа показывает до трёх обращений по
ближайшему сроку и позволяет перейти прямо к переписке; просрочка пересчитывается раз в минуту. Клиент видит только свои
открытые, ожидающие и решённые обращения. Все показатели получены из доступного роли состояния сервиса.

Визуальная приёмка: вход владельца и клиента, создание обращения, пустой поиск, ответ и внутренняя заметка,
смена статуса, база знаний и навигация на экране 390 px. Сборка не заменяет прохождение этих сценариев.

## Запуск

Node 24 рекомендуется. Из этого каталога:

```sh
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:3810. Данные — в `support-data`; порт и каталог меняют `SERVICE_PORT` и `SERVICE_DATA_DIR`. Для разработки — `npm run dev` при работающем сервере. `.env.example` описывает переменные, `.env` автоматически не читается. `SERVICE_DEMO=0` с **новым** каталогом данных даёт пустой экземпляр без демопаролей.

`npm run start:node` с `SERVICE_UPSTREAM`, своим `SERVICE_NODE_ID` и теми же `SERVICE_TOKEN_SECRET`/`SERVICE_NODE_TOKEN` добавляет обслуживающий узел: чтения и подключения распределяются, команды идут владельцу записи.

## Роли и демоданные

| Аккаунт | Пароль | Путь |
| --- | --- | --- |
| owner | owner-pass | Организация, команда, приглашения, статьи, вся поддержка |
| lead | lead-pass | Распределение обращений, статьи и команда в пределах роли |
| agent | agent-pass | Принять обращение, закрытая заметка, черновик, ответ |
| customer | customer-pass | Создать обращение, ответить, приложить файл; только свои обращения |
| outsider | outsider-pass | Другая организация Harbor; данные Northstar недоступны |

Демонстрация: клиент создаёт обращение и прикладывает файл → оператор видит его без перезагрузки, принимает и пишет закрытую заметку → готовит материал помощником и отправляет ответ отдельным действием → руководитель меняет приоритет, срок и исполнителя, а конкурирующая правка старой версии отклоняется → владелец отзывает участие, и ранее открытые чтения и ресурсы теряют доступ.

Сотрудники дополнительно ведут доску задач: ручная задача или задача из обращения по явному подтверждению, исполнитель, срок, список проверок. Клиенту раздел недоступен, при отзыве роли доска закрывается без перезагрузки.

Поиск переписки показывает применённый запрос и число загруженных совпадений. Изменённый текст применяется
после нажатия «Найти в переписке»; «Очистить поиск» возвращает обычную переписку без результатов поиска.

Продуктовый поиск принимает отдельную машинную идентичность с правом `knowledge:search` только своей организации.
Владелец открывает раздел «Ключи интеграций»: выпуск на 1–90 дней, список по текущей организации и отзыв.
Выпуск и список используют ресурс `productKeys`, отзыв — серверную команду. Секрет показывается один раз;
копирование выполняется отдельной кнопкой. При смене организации, раздела или выходе секрет исчезает.
Повтор после потерянного ответа с теми же параметрами сохраняет requestId; если ключ уже создан, секрет повторно не выдаётся.
Пользовательский вход сохраняется; машинный ключ не читает обращения, заметки и административные представления.
Подробности login, поиска и отзыва — в [API](API.md).

## Границы

- Вся запись принадлежит одному authority; разные authority не должны писать в один каталог. Обслуживающие узлы — это распределение чтений, а не горизонтальное масштабирование писателя.
- Помощник подбирает выдержки из опубликованных статей: это **не языковая модель**, платных запросов нет. `DraftProvider` — заменяемая граница подключения модели, внешний исполнитель задаётся серверной композицией, не браузером.
- Пределы экземпляра: 64 организации, 500 обращений на организацию, 200 сообщений на обращение, 200 статей и 20 их версий, 10 файлов на обращение, 100 вложений по 512 КиБ, одна активная попытка ИИ на аккаунт и 100 сохранённых запусков. Это не заменяет общий rate limit на сетевой границе.
- Уведомления — события внутри приложения и локальный тестовый журнал почты; письма наружу не отправляются.
- Внешний вход — [адаптер OIDC](OIDC.md), проверенный локальным сервером. Реальный провайдер и HTTPS требуют своей конфигурации; внешняя личность сама по себе не даёт членства.
- Секреты сессий передаются окружением и не входят в образ. Резервная копия — **весь** каталог данных при остановленном authority: журнал не заменяет копию вложений.
- Ответ и заметка меняют обращение одной командой; отдельного `createConversationHost` нет — [разбор](../../doc/reports/conversation-host-comparison.md).

## Проверки

```sh
npm run typecheck
npm test
npm run build
```

`npm test` поднимает настоящие локальные сокеты, authority и два обслуживающих процесса: изоляция организаций, закрытые заметки, приглашения, повтор команд, конфликт версии, отзыв доступа, сбой узла, рестарт, бинарные вложения, отмена и поздний ответ помощника, страницы архива и конкурентное добавление, индекс статей, продуктовый HTTP-фасад и OIDC (подпись, issuer/audience/nonce, PKCE, истечение, однократность обмена).

Размещение проверяет `npm run test:support` из `apps/hosting`: два образа, обновление и откат, постоянный адрес, сохранённые обращения и точные байты вложений, контейнер 256 МиБ. Формат данных обоих образов `support-1`; это не означает совместимость произвольной миграции.

Холодная копия и восстановление — `npm run test:backup`.
