# Northstar — поддержка команды

<!-- status:versions -->
Текущие зависимости: **common2 2.21.1 / react2 3.5.1**.
<!-- /status:versions -->

Самостоятельный SaaS-пример: организации и приглашения, обращения, закрытые заметки, исполнители и сроки, версия базы знаний, вложения и помощник с источниками. `wenay-common2@2.21.1` обеспечивает команды, роли, журнал, сессии, репликацию, переподключение и ресурсы. `wenay-react2@3.5.1` — жизненный цикл React-клиентов, подписки и таблицы. Используются только опубликованные API.

## Запуск

Node 24 рекомендуется. Из этого каталога:

```sh
npm ci
npm run build
npm start
```

Открыть http://127.0.0.1:3810. Данные сохраняются в `support-data`. Для разработки отдельно `npm run dev`; сервер должен продолжать работать. `.env.example` описывает переменные; приложение не загружает `.env` автоматически.

| Аккаунт | Пароль | Путь |
| --- | --- | --- |
| owner | owner-pass | Организация, команда, приглашения, статьи, вся поддержка |
| lead | lead-pass | Распределение обращений, статьи и команда в пределах роли |
| agent | agent-pass | Принять обращение, закрытая заметка, черновик, ответ |
| customer | customer-pass | Создать обращение, ответить, приложить файл; только свои обращения |
| outsider | outsider-pass | Другая организация Harbor; данные Northstar недоступны |

Для внешнего входа есть [адаптер OIDC](OIDC.md). `SERVICE_DEMO=0` и **новый** каталог данных дают пустой экземпляр без демопаролей. Внешняя личность сама по себе не даёт членства: пользователь создаёт команду или принимает приглашение. Протокол проверен локальным OIDC-сервером, реальный внешний провайдер и HTTPS-размещение требуют своей конфигурации.

## Демонстрация

1. Клиент создаёт обращение и прикладывает файл.
2. Оператор видит его без перезагрузки, принимает и пишет внутреннюю заметку. Клиент заметку не получает.
3. Оператор выбирает «Подготовить материал». Тестовый исполнитель находит опубликованные статьи; платных запросов нет. Это подбор выдержек, **не настоящая языковая модель**.
4. Перед вставкой сервер проверяет актуальные права, обращение и версии источников. Пользователь отправляет ответ отдельным действием.
5. Руководитель меняет приоритет, срок и исполнителя. Конкурирующая правка старой версии отклоняется.
6. Владелец отзывает участие: ранее открытые чтения и ресурсы также теряют доступ.

## Границы и фасады

`backend/service.ts` задаёт сервис; `domain.ts` содержит предметные команды и проекцию `workspace`. Источник полномочий — текущие членства в серверном состоянии. Клиентский `orgId` всегда проверяется. Системная `identityProvision` доступна только серверному аккаунту.

`runtime.ts` соединяет сервис с `resources.assistant` и `resources.files`. Частные результаты читаются через `control` с повторной проверкой прав после IO. Байты файлов и тексты ответов ИИ не размножаются в общей проекции. `DraftProvider` — заменяемая граница подключения модели; внешний исполнитель задаётся серверной композицией, не браузером.

Вся запись принадлежит одному authority. `npm run start:node` с `SERVICE_UPSTREAM`, уникальным `SERVICE_NODE_ID` и теми же `SERVICE_TOKEN_SECRET`/`SERVICE_NODE_TOKEN` добавляет обслуживающий узел. Чтение и подключения распределяются, команды идут владельцу записи. Это не горизонтальное масштабирование единственного писателя. Разные authority не должны писать в один каталог.

Стабильные секреты сессий надо передавать через окружение при рестартах. Без них локальные данные сохраняются, но старый вход может потребовать повторной авторизации. Секреты не входят в образ. Для резервной копии останавливайте authority и копируйте **весь** каталог данных вместе с частными файлами/контрольными точками; журнал сам по себе не заменяет резервную копию вложений.

## Проверки и ограничения

```sh
npm run typecheck
npm test
npm run build
```

Проверки используют реальные локальные сокеты, authority и два обслуживающих процесса: разные организации, закрытые заметки, приглашения, повтор команд, конфликт версии, отзыв доступа, сбой узла, рестарт, бинарные вложения, отмену и поздний ответ исполнителя. OIDC-проверка включает подпись, issuer/audience/nonce, PKCE, истечение и однократность обмена. В браузере проверены вход и перенос материала в черновик; документы UI-приёмки продолжают дополняться.

Хостинг проверяет `apps/hosting/backend/support-live-check.ts`: два образа, обновление и откат, постоянный адрес, сохранённые обращения/вложения и подключённая сессия. Контейнер ограничен 256 МиБ. Образы предварительно собираются с `APP_RELEASE=first`/`second`; формат данных обоих `support-1`, проверка не означает совместимость произвольной миграции.

Текущие пределы экземпляра: 64 организации, 500 обращений на организацию, 200 сообщений на обращение, 200 статей, 20 исторических версий статьи; до 10 файлов на обращение, 100 вложений всего, 512 КиБ каждый. AI: одна активная попытка на аккаунт, 100 сохранённых запусков. Это ограниченный пример; архив/постраничная выдача истории и массовое индексирование ещё не реализованы. Ограничение количества не заменяет общий rate limit на сетевой границе.

Ответы и заметки атомарны с изменением обращения в schemaCommand; отдельный дублирующий conversationHost для той же переписки не создан. Настройки уведомлений и промышленная политика хранения остаются задачами приложения. Это не требования добавить предметную логику в библиотеку.

## Задачи команды — H06

Сотрудники открывают отдельную доску: ручные задачи, исполнитель, срок, приоритет, описание и список проверок. Владелец/руководитель видят задачи организации; специалист — созданные им или назначенные ему. Клиенту раздел недоступен. При отзыве роли открытая доска закрывается, интерфейс возвращается к обращениям.

В обращении действие «Создать задачу из обращения» сначала показывает подтверждение. Одна задача привязывается к обращению; повтор не создаёт дубликат. Это явное действие человека: последующие изменения переписки не перезаписывают карточку. Детали остаются в исходной переписке.

Прикладные `organizer/task-domain.ts` и `task-model.ts` выделены из пиццерии; адаптер `backend/organizer.ts` подставляет разрешённую организацию и актуальную роль. Доставка `taskBoards`, команды и квитанции принадлежат common2. Перетаскивание мышью/клавиатурой обеспечивает публичный `useReorderBoard` react2; статус можно выбрать и обычным списком. Завершить задачу с непроверенными пунктами нельзя. Это переиспользование предметного блока между примерами, а не добавление задач пиццерии в библиотеку.

Браузерная приёмка 10.09.2026: подтверждение создания из обращения, ручная задача, редактирование срока/описания, checklist, запрет преждевременного завершения, перенос мышью в пустую колонку и клавиатурой между колонками, живое снятие/возврат роли сотрудника с закрытием доски без reload, смена аккаунтов owner/customer/outsider и пустая доска Harbor. При ширине 390 px страница не имеет горизонтального переполнения; колонки идут вертикально. Новый `useStoreReplayMirror` проверен подготовкой материала помощника и вставкой в неотправленный черновик, выходом и входом другой ролью. Загрузка файла через расширение Chrome недоступна без разрешения доступа к file URLs; серверные/сетевые проверки файлов пройдены отдельно.

## Что дало использование библиотек

Прикладной код задаёт роли, изменения и ресурсы. Авторизация команд, квитанции повторов, доставка состояния, выбор узла и восстановление соединения переиспользуются. Для двух ресурсов небольшой `shared/react/replay-view.ts` соединяет публичные `useStoreReplayMirror` и `useClientStore`: создание зеркала, подписка, терминальная ошибка и очистка принадлежат react2.

Три подтверждённых ограничения common2 описаны в `doc/library-tasks` репозитория: `AI-POLICY-INVALIDATION`, `AI-RESOURCE-LIFECYCLE`, `STORE-NESTED-REPLACEMENT`. В этом примере тексты ИИ выдаются отдельным защищённым чтением, клиент подписывается на состояние с `onError`, вложенная история копируется в обычные объекты перед заменой. Эти меры не объявляют библиотечные дефекты исправленными.

# Публикации внешней контент-студии

Необязательный `CONTENT_CONNECTIONS_JSON` — server-only карта support org → настроенный Content origin/organization/reader. Например, для локального стенда значение процесса:

```json
{"northstar":{"url":"http://127.0.0.1:3817","orgId":"northstar","account":"reader","password":"reader-pass"}}
```

Для внешнего сервиса используйте выделенную reader-учётную запись и передавайте секрет через защищённое окружение. Конфигурация не отправляется в UI и не выбирается клиентом. Endpoint CMS обязан быть сервисом content; отдельный common2 client открывает только `published` authority resource, без команд и редакторских views. `identity.me()` проверяется при каждом чтении: writer/editor/publisher/owner credentials отклоняются. Public CMS contract принадлежит студии и проверяется там через satisfies; копия `published-contract.ts` остаётся небольшим типом потребителя.

`content.control.list(supportOrgId)` возвращает `{configured,articles}`, `read({orgId,slug})` — текущую опубликованную версию. ACL организации поддержки проверяется до и после remote IO. Нет кеша результатов на сервере: снятая публикация отказывает при следующем чтении. Отсутствующая настройка показывает спокойное состояние «не подключено». Ошибка источника не заменяется старым текстом или копией в local articles. База знаний UI отдельно показывает read-only публикации: текст/цитаты/ссылки, изображения как описание. Запрошенная статья является снимком, показано время чтения; обновите её для проверки новой версии.

`apps/content/backend/integration-check.ts` проверяет два настоящих сервиса: draft/review privacy, reader-only, tenant mapping, publish/withdraw/rollback, неизменность local articles, отзыв роли во время чтения и offline. Запуск из исходного `apps/content`: `npm run test:integration`. Эта межпроектная проверка не является зависимостью самостоятельной поддержки. Подключение не изменяет источники AI-помощника поддержки.

## Архив переписки и индекс

В `views.workspace` входят последние 20 разрешённых сообщений и `messageCount`. Предыдущие сообщения и поиск по всей истории доступны через `resources.conversation.control.page({orgId,ticketId,beforeId,query,limit})`: до 50 записей, курсор — идентификатор граничного сообщения. Ответ содержит `messages`, `nextBeforeId`, `total`, `revision`. Новые ответы не сдвигают ранее полученную границу; чужая или скрытая граница отклоняется. В UI архив открывается порциями по20; смена версии/роли закрывает прежний материал. Полная история сохраняется на authority, предел200сообщений на обращение остаётся явным ограничением примера.

Нормализованный локальный индекс статей хранит организацию и revision. `createReconciler` обновляет его по изменениям; запрос немедленно проверяет опубликованность/версию/членство по исходному состоянию. Только что опубликованная версия индексируется при первом запросе, снятая исключается сразу. Индекс восстанавливается из основного архива и не требует второго durable писателя. Модели, embeddings и внешнего поиска нет.

## Узкий продуктовый API поиска

На authority доступен `POST /api/product/search/published`, описание — `GET /api/product/openapi.json`. Реализация использует публичные `createHttpFacadeServer`/`createHttpFacadeOpenApi` common2, а тип входа, проверка и OpenAPI выводятся из одного `SEARCH_INPUT` через `InferInput`/`buildInputValidate`/`inputJsonSchema`.

Вход — стандартный bearer сервиса; пример для Node22+, без установки другого SDK:

```js
const origin = 'http://127.0.0.1:3810'
const login = await fetch(origin + '/api/support/login', {
    method: 'POST', headers: {'content-type': 'application/json'},
    body: JSON.stringify({args: [{account: 'customer', password: 'customer-pass'}]})
}).then(response => response.json())
const result = await fetch(origin + '/api/product/search/published', {
    method: 'POST', headers: {'content-type': 'application/json', authorization: 'Bearer ' + login.value.token},
    body: JSON.stringify({args: [{orgId: 'northstar', query: 'приглашение', limit: 3, requestId: crypto.randomUUID()}]})
}).then(response => response.json())
console.log(result)
```

Фасад выдаёт только текущие опубликованные статьи; административных методов в этом OpenAPI нет. Проверяются членство, типы, размер запроса, лимит выдачи и версия источника. Ответ `no-store`; это свежее чтение без кеширования текста в квитанции команды. Если подключён Metering, поиск резервирует одну тестовую единицу через уже используемый адаптер, повтор requestId не выполняет операцию повторно. Доставку результата при сетевой неопределённости не объявляем exactly-once.

HTTP-продуктовая поверхность находится на authority. На serving-узлах остаются обычные SC1 представления/ресурсы и UI; для HTTP маршрутизируйте `/api/product/*` на authority. Стандартный пользовательский bearer в этом примере не является отдельным машинным API-ключом: scopes/ротация API-ключей показываются в Counter. Отдельная машина должна получить свою ограниченную идентичность, а не пароль владельца.

`conversation-check.ts`, `article-index-check.ts`, `product-check.ts` проверяют страницы и конкурентное добавление, поиск старых сообщений, приватность/отзыв, обновление индекса и реальный HTTP/OpenAPI. Полная регрессия после этих дополнений обязательна; предыдущий Docker отчёт не заменяет новую приёмку образа.
