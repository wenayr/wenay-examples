# Первичное заполнение фото гостиниц

Команды выполняются из `apps/travel` на Node.js 24.2 или новее. Источники изображений проверяет сервер. В карточку попадают URL снимка и оригинала, автор и лицензия. Публичный справочник и коммерческие тарифы используют разные идентификаторы.

## Проверка и заполнение

```sh
npm run photos:import -- --dry-run --destination hurghada --limit 20
npm run photos:import -- --all
```

Первая команда проверяет ограниченную выборку и выводит результат без изменения фотографий. Вторая обрабатывает каталог порциями. Рядом с рабочим манифестом импортёр ведёт служебный журнал проверок SQLite. Для комплектного манифеста журнал находится в `data/photos-import.sqlite`. Без флагов обрабатываются до 20 ближайших записей. Не изменившиеся цели повторно проверяются через 14 дней. Тот же вызов можно повторить после остановки. Для отдельного отеля используйте, например, `npm run photos:import -- --key Q111400547 --force`.

Собранный каталог использует `backend/property-photo-manifest.json`. Для рабочего сервера укажите отдельный файл постоянного тома через `TRAVEL_PHOTO_MANIFEST` и выставьте одинаковое значение для сервера и импорта. При первичной настройке скопируйте комплектный манифест в этот файл, чтобы сразу показывать уже найденные снимки. Отдельный запуск импортёра принимает путь через `--manifest`.

Для регулярной проверки подойдёт существующий планировщик сервера. Например, запись crontab ниже запускает обработку до 50 подходящих записей каждые 15 минут. Подставьте свой путь к checkout, каталог данных и путь к npm, доступному в окружении cron. Каталог данных и файл `property-photos.json` подготовьте один раз.

```cron
*/15 * * * * cd /srv/wenay-examples/apps/travel && TRAVEL_PHOTO_MANIFEST=/srv/wenay-data/property-photos.json /usr/bin/npm run photos:import -- --limit 50
```

Сетевые ошибки сохраняют последнюю проверенную фотографию. После записи очередного результата работающий сервер перечитывает изменения. Открытая карточка получает новое изображение или показывает «Фото объекта пока нет» после подтверждённого удаления.

## Как устанавливается связь с гостиницей

- Для записи Wikidata импортёр получает свойство изображения `P18` по идентификатору отеля. Запись OpenStreetMap может указывать тот же идентификатор через явный тег `wikidata`.
- Для записи OpenStreetMap также используется файл, на который прямо указывает тег `wikimedia_commons` или `image` объекта. Ссылка на сайт гостиницы и совпадение координат сами по себе не подтверждают права на фотографию.
- Список `backend/photos/commons-links.json` содержит выверенные вручную связи с файлом оригинала. Например, категория Wikidata P373 связывает конкретную гостиницу с её категорией Commons. Кандидат из категории проходит проверку изображения и прав перед включением. Дополнительный согласованный список может быть передан через `--candidates`. Формат записи: `{"hotelKey":"Q110774963","title":"File:AyanaResort01.jpg","matchedBy":"reviewed-commons-category","evidenceUrl":"https://commons.wikimedia.org/wiki/Category:Ayana_Resort,_Bali"}`.
- Для выбранного файла источником имени фотографа, лицензии и адреса изображения служит API Wikimedia Commons. Импортёр сохраняет доказанную связь, оригинальный идентификатор и атрибуцию. В `backend/property-photo-exclusions.json` перечислены проверенные пары «объект + файл», для которых ранее была обнаружена ошибка идентификации или фотография прежнего объекта.
- Гостиницы без подтверждённого снимка остаются в поиске. Подключённые отдельно коммерческие партнёры могут передавать изображения по условиям своего договора.
