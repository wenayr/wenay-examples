# Поиск туров по гибким датам

Первый сценарий приложения для подбора и покупки тура в чате. Человек задаёт город вылета, окно возможных дат, длительность поездки, состав группы и бюджет. Карта и график конкретного отеля должны показывать предложения из одного результата поиска.

## Запуск

Для этого расчёта достаточно Node.js 24.2 или новее. Из каталога `apps/travel`:

```sh
node demo/january.ts
node --test test/search-tours.test.ts
```

Пример использует вымышленные отели и цены. Вылет из Москвы с 15 по 31 января 2027 года, поездка на 10 дней для двоих. При бюджете 90–110 тыс. ₽ подходят отель A с вылетом 19 января за 98 тыс. ₽ и отель B с вылетом 31 января за 110 тыс. ₽. Окно ограничивает дату вылета. Возвращение возможно в феврале.

## Контракт поиска

`searchTours` получает нормализованные предложения поставщиков. Каждая запись представляет доступный вариант пакета по единой цене за всю группу с перелётом туда и обратно и проживанием. Суммы задаются в минимальных единицах валюты, для рублей это копейки.

- Для карты `hotelId` связывает результат с координатами отеля в каталоге, а `best` содержит самое дешёвое предложение в пределах бюджета. Обе границы диапазона включены.
- Для графика `calendar` содержит каждую дату вылета. В `lowest` лежит самое дешёвое доступное предложение дня, в `inBudget` — самое дешёвое в выбранном диапазоне. Например, при нижней границе 90 тыс. ₽ на одну дату могут быть тарифы и за 85 тыс. ₽, и за 98 тыс. ₽. На карте отель остаётся виден с ценой 98 тыс. ₽.
- Если данных на дату нет, оба значения равны `null`. График может оставить разрыв. Идентификатор конкретного предложения сохраняется до выбора клиентом.

Следующий шаг — вывести эти данные на карте и в карточке отеля на `wenay-react2`. Затем подключить поиск к веб-интерфейсу и инструменту MCP через общий серверный метод на `wenay-common2`. Для оформления в чате нужны актуальное предложение поставщика, повторная проверка суммы и наличия, подтверждение клиентом и обработка результата бронирования.
