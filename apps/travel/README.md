# Wenay Travel · туры из Таллина

Основная страница открывает справочник реальных средств размещения. Выберите направление, источник, текстовый запрос или область карты. Каждая страница загружает свою порцию объектов через сервер. Открытые карта, список и карточка подписываются на изменения текущего региона. В данных указаны источник, время его проверки и доступность снимка. При повторном открытии восстанавливаются последние параметры.

В разделе [пакетных туров](#пакетные-туры) TEZ TOUR Eesti можно выбрать окно вылета, продолжительность и бюджет за двоих, найти гостиницу на карте и открыть её цены по датам. Поддерживаются вылеты из Таллина в Хургаду, Шарм-эль-Шейх и на Родос.

## Запуск

Нужен Node.js 24.2 или новее. Из корня репозитория:

```sh
cd apps/travel
npm ci
npm run build
npm start
```

Откройте **http://127.0.0.1:3820/**. Сервер читает сборку из `dist/`; порт можно переопределить переменной `SERVICE_PORT`. Для разработки с обновлением страницы используйте `npm run dev`. Для запуска через общую витрину откройте второй терминал в корне репозитория, запустите `node apps/catalog/server.mjs` и найдите Wenay Travel по адресу http://127.0.0.1:3800/.

## Источники и API

- `GET /api/travel/destinations` возвращает поддерживаемые регионы и источники.
- `GET /api/travel/packages` подбирает отели оператора. Передайте `destination`, `firstDeparture`, `lastDeparture` и `nights`. Границы `minTotal` и `maxTotal` задаются в евроцентах за весь пакет. При необходимости добавьте `minStars`, `west/south/east/north`, `offset` и `limit`. Ответ содержит страницу карточек и до 200 меток с подтверждёнными координатами.
- `GET /api/travel/package-calendar` принимает те же условия поездки и `hotelId` оператора, например `tez:1061`. Для каждого дня возвращаются минимальная наблюдаемая цена, подходящее предложение в бюджете, время и полнота проверки.
- `GET /api/travel/catalog?destination=hurghada&offset=0&limit=24` выдаёт страницу уникальных объектов и состояние источников. Можно передать `q`, `source`, четыре границы карты `west/south/east/north`. Для следующей страницы используйте `nextOffset`. Сортировка сначала показывает объекты с атрибутированным собственным фото, затем упорядочивает по имени и ID.
- `GET /api/travel/options?destination=hurghada&checkIn=2027-01-24&checkOut=2027-01-31&adults=2` проверяет пакетные цены у туроператора. Если передать `hotelId` из справочника, ответ содержит адреса поиска именно с этим объектом у посредников. Метки ответа отделяют живую цену от перехода на поиск и указывают время получения данных.
- Справочные данные поступают из OpenStreetMap и Wikidata. Для ирландских городов также используется государственный реестр Fáilte Ireland. Фильтрация и перемещение карты работают по последнему набору региона. Сервер обновляет просроченные источники при обращении к региону и продолжает опрос, пока в регионе открыта подписка. Срок актуальности — 12 часов, пауза после ошибки — 15 минут. Успешные обновления записываются на диск. При отсутствии сети доступны последние полученные или комплектные данные.
- Включённые посредники, правила передачи клиента и условия комиссионного подключения описаны в [PARTNERS.md](PARTNERS.md). Справочные данные не гарантируют наличие номеров, а тариф поставщика подлежит перепроверке у продавца. Момент получения тарифа виден в интерфейсе.

Фотографии объектов можно получить и обновить из источников через [импорт фотографий](PHOTO-IMPORT.md).

## Пакетные туры

Откройте `/#packages`. Выберите от одной до 20 дат вылета и число ночей. Бюджет применяется к стоимости всего пакета для двух взрослых. TEZ группирует региональный ответ по отелям, оставляя самое дешёвое предложение в запрошенном диапазоне. Например, минимальный тариф может оказаться ниже вашего бюджета, а следующий тариф той же гостиницы — подходить. Критерии бюджета поступают к оператору до группировки.

Карта использует координаты, подтверждённые на страницах конкретных отелей TEZ. На момент поставки они есть у 13 гостиниц. Остальные подходящие гостиницы доступны в списке без ограничения по области. При перемещении карты поиск использует уже полученную выборку поездки. Результаты нового поиска по другим датам или бюджету запрашиваются у оператора.

Откройте карточку гостиницы, чтобы увидеть график. Для каждого дня поставщик получает отдельный запрос по идентификатору этой гостиницы с выбранной длительностью. Самый дешёвый наблюдаемый вариант и самый дешёвый вариант в бюджете могут различаться. Если поставщик не ответил, день помечается как непроверенный. Положительный ответ допускает повторное использование в течение двух минут. При временном сбое ранее проверенные цены могут показываться до 15 минут с исходным временем наблюдения.

## Обновления во время просмотра

В отдельном терминале из `apps/travel` можно запросить актуальный набор гостиниц для региона:

```sh
node backend/places/refresh.mjs wikidata hurghada
```

Фоновые запросы веб-сервера и эта команда используют общие файлы поколений в `travel-data/places/`. Чтобы вынести их на постоянный том, задайте одинаковый путь `TRAVEL_SNAPSHOT_DIR` для сервера и импортёров. Чтобы наполнять каталог только внешним импортёром, запустите веб-сервер с `TRAVEL_REFRESH_MODE=manual`. Карточки, поиск и подписка продолжат работать. Сервер может работать с несколькими процессами-читателями на одной файловой системе, поддерживающей атомарный rename; каждый читатель отслеживает состояние файлов. Запрашивать напрямую у источников с одинаковой частотой со всех реплик не требуется.

Для передачи изменений браузеру сервер использует журнал региона из `wenay-common2/replay`. Список содержит курсор `revision`. Браузер открывает один поток `GET /api/travel/events?destination=hurghada&since=<revision>` через EventSource. Односторонний SSE работает на том же HTTP-порту и переоткрывает соединение со стандартным заголовком `Last-Event-ID`. Событие `catalog` передаёт только направление и текущую версию. Клиент перечитывает активную страницу поиска и открытую карточку (`GET /api/travel/hotel?destination=…&hotelId=…`), сохраняя фильтры. После истечения окна в 64 изменения, смены процесса или неверного курсора приходит `reset`: браузер читает актуальное состояние. Медленное соединение с заполненным буфером закрывается, а у переподключившегося клиента действует тот же протокол. После перезапуска сервер берёт актуальные файлы с диска; старый курсор вызывает повторное чтение. Для прокси требуется потоковая передача SSE.

Первичное заполнение и периодический повтор импорта фото описаны в [PHOTO-IMPORT.md](PHOTO-IMPORT.md). Браузерная проверка с атомарной публикацией фото, отключением сети, перезапуском сервера и снятием гостиницы запускается после сборки: `node scripts/check-live-directory.mjs`. Для неё нужны Playwright и доступный Chromium.

Справочники OSM, Wikidata и Fáilte Ireland опрашиваются по HTTP. Файловый импорт может изменить сведения, фотографию или убрать запись из полного регионального набора. Неуспешный запрос сохраняет предыдущие данные; неполная выборка сохраняет уже известные записи. Фоновая проверка затрагивает только сведения об отелях. Наличие и стоимость пакетного тура запрашиваются отдельно у продавца при поиске.

## Пример расчёта по датам

Откройте `/#demo` для автономного примера. В этом режиме девять вымышленных отелей с демонстрационными ценами в евро, включая перелёт из Таллина и проживание на двоих на 10 дней. В `/#catalog` находится основной динамический каталог.

1. Задайте интересующие даты вылета и бюджет за всю поездку. Стартовый диапазон с 15 по 31 января 2027 года, от 0 до 3800 €. Каждый отель в выдаче имеет хотя бы один подходящий тариф.
2. Выберите отель на карте или откройте его карточку. На графике видны минимум дня и минимальная цена в бюджете. Если на одну дату минимальный тариф дешевле нижней границы, более дорогой тариф может подходить. Дни без предложений остаются пустыми.
3. Выберите подходящую дату. Интерфейс покажет конкретный тур и полную цену. Параметры поиска и выбор можно восстановить при следующем открытии в том же браузере.
4. Создайте демозаявку, чтобы проверить путь клиента до подтверждения выбора. Рабочие варианты подключения поставщиков описаны в [справке о партнёрах](PARTNERS.md).

Цены, доступность и предложения демонстрационные. Фотографии иллюстрируют направления. Пользователь может выбирать туры без обращения к поставщику или платёжному сервису.

## Код и проверка

```sh
npm run typecheck
npm test
npm run demo
```

- `demo/catalog.ts` связывает направления, координаты отелей и тарифы с датами вылета. Идентификаторы выведены из исходного каталога.
- `src/search-tours.ts` формирует общие для карты и графика результаты. В поисковом запросе суммы указаны в минимальных единицах валюты, для евро это центы.
- `frontend/state.ts` использует `wenay-common2/observe`, компоненты подписываются на выбранные данные через `wenay-react2/react`.
- `src/inquiry.ts` задаёт границу локальной демонстрационной заявки.

Для приёма денег и подтверждения бронирования требуется договор с выбранным каналом и выдача серверных полномочий. В этой версии заказ у поставщика завершает путешественник на стороне партнёра.
