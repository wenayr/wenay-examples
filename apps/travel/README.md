# Поиск туров по гибким датам

Первый сценарий приложения для подбора и покупки тура в чате. Человек задаёт город вылета, окно возможных дат, длительность поездки, состав группы и бюджет. Карта и график конкретного отеля должны показывать предложения из одного результата поиска.

## Запуск

Из каталога `apps/travel`, с Node.js 24.2 или новее:

```sh
npm ci
npm run dev
```

Откройте адрес Vite из терминала. `npm run build` проверяет типы и создаёт статическую сборку в `dist/`. `npm test` запускает тесты поиска. Чтобы проверить отдельно минимальный пример с двумя подходящими отелями, выполните `npm run demo`.

## Проверка интерфейса

В демонстрационном каталоге четыре вымышленных отеля. Стоимость включает перелёт туда и обратно из Москвы и проживание для двух туристов на 10 дней. Даты 15–31 января 2027 года относятся к вылету. Возвращение может приходиться на февраль.

1. В исходном диапазоне 90–110 тыс. ₽ на карте три отеля. Маркер показывает минимальную подходящую цену за поездку.
2. Выберите Palm Bay и 19 января. Минимум этого дня — 85 тыс. ₽, выбранный тариф в бюджете — 98 тыс. ₽. Даты без предложений показаны прочерком.
3. Увеличьте верхнюю границу до 125 тыс. ₽. Появится Coral Garden, от 120 тыс. ₽. При равных границах 90 тыс. ₽ подходящих предложений нет. Кнопка «Сбросить» возвращает исходный поиск.
4. Нажмите на маркер или название отеля для просмотра графика. Схема побережья работает без сети. Кнопка «Подробная карта» включает тайлы OpenStreetMap.

## Модель и библиотеки

В `demo/catalog.ts` тип `HotelId` выводится из ключей каталога отелей. Матрица цен проверяется через `satisfies Record<HotelId, DailyPrices>`: у каждого отеля есть строка, а внутри строки перечислены только даты с ценами. Внешние данные поставщиков должны проходить отдельную проверку при получении.

Расчёт в `src/search-tours.ts` принимает предложения и параметры поиска и возвращает данные для карты и графика. `frontend/state.ts` создаёт хранилище через `wenay-common2/observe`. Компоненты получают его данные через `useStoreNode` из `wenay-react2/react`.

## Контракт поиска

`searchTours` получает нормализованные предложения поставщиков. Каждая запись представляет доступный вариант пакета по единой цене за всю группу с перелётом туда и обратно и проживанием. Суммы задаются в минимальных единицах валюты, для рублей это копейки.

- Для карты `hotelId` связывает результат с координатами отеля в каталоге, а `best` содержит самое дешёвое предложение в пределах бюджета. Обе границы диапазона включены.
- Для графика `calendar` содержит каждую дату вылета. В `lowest` лежит самое дешёвое доступное предложение дня, в `inBudget` — самое дешёвое в выбранном диапазоне. Например, при нижней границе 90 тыс. ₽ на одну дату могут быть тарифы и за 85 тыс. ₽, и за 98 тыс. ₽. На карте отель остаётся виден с ценой 98 тыс. ₽.
- Если данных на дату нет, оба значения равны `null`. График может оставить разрыв. Идентификатор конкретного предложения сохраняется до выбора клиентом.

Следующий этап — связать веб-интерфейс и ИИ-чат с одним серверным методом поиска через MCP, подключить поставщика и перед оформлением перепроверять цену и наличие выбранного предложения. В этой версии используются демонстрационные данные.
