# Каталоги размещения

Каталог включает картографические точки размещения и записи реестров. Наличие номера, доступность для конкретных дат и договор с объектом подтверждает коммерческий поставщик. Метаданные `price` и `photo` этих трёх источников равны `null`. Фотографии с собственной подтверждённой лицензией подключаются отдельно.

| Источник | Что отбираем | Источник и лицензия |
| --- | --- | --- |
| OpenStreetMap contributors | Именованные гостиницы и другие типы размещения внутри прямоугольника курорта. У полигонов координата соответствует центру ограничивающего прямоугольника. | [Данные OpenStreetMap](https://www.openstreetmap.org), [ODbL 1.0](https://www.openstreetmap.org/copyright), [условия общих серверов Overpass](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html) |
| Wikidata | Объекты с классом гостиницы или производным классом и координатами в регионе. Исключены известные даты ликвидации и прошедшая дата закрытия. | [Сервис SPARQL](https://www.wikidata.org/wiki/Wikidata:SPARQL_query_service), [CC0](https://www.wikidata.org/wiki/Wikidata:Licensing) |
| Fáilte Ireland | Отели, B&B, хостелы, гостевые дома и апартаменты с регистрационным номером и координатами из национального реестра Ирландии. | [Государственный реестр и API](https://data.gov.ie/dataset/national-quality-assurance-framework-register-of-accommodation), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) |

Каждый файл в `snapshots` — отдельная адаптированная выборка указанного источника. Для выборок OpenStreetMap действует ODbL 1.0, для выборок Fáilte Ireland действует CC BY 4.0. Формат изменён. В рабочем контракте сохраняются идентификатор, происхождение и разрешённые сведения записи. Интерфейс указывает исходный каталог и его лицензию. Соответствие между поставщиками служит навигацией между записями; исходные выборки и их лицензии остаются доступными независимо. Имена владельцев и контакты физических лиц из реестра Fáilte Ireland не импортируются. Время `fetchedAt` обозначает момент получения выборки. При успешном ответе с пустым списком время также сохраняется. Отсутствие полученной выборки обозначается значением null. Записи могут отставать от реального состояния гостиницы.

## Обновление

Из `apps/travel`:

```sh
node backend/places/refresh.mjs
node backend/places/refresh.mjs wikidata phuket
node --test backend/places/places.test.mjs
```

Загрузка разрешена только для регионов в `registry.mjs`. Ограничения одного ответа: до 1000 объектов OpenStreetMap и 350 строк Wikidata до удаления повторов. Отсутствие гостиницы в выборке не определяет её наличие или статус бронирования. CLI обновляет снимки атомарно. При сетевой ошибке ранее сохранённая выборка остаётся на диске. При массовом запуске на один источник приходится один одновременный запрос. Ответ HTTP 429 останавливает оставшиеся запросы к этому источнику в данном запуске. Для регулярного коммерческого трафика учитывайте рекомендации оператора общего сервера Overpass о собственной инфраструктуре.

### Рабочие поколения и индексы

CLI и обновления сервера публикуют один файл на источник и направление в `apps/travel/travel-data/places/`. Для рабочего каталога на другом диске или общего каталога нескольких процессов задайте одинаковый абсолютный `TRAVEL_SNAPSHOT_DIR`. Чтобы результаты переживали перезапуск контейнера, подключите для него постоянный диск. До первой загрузки источник использует комплектный снимок из `backend/places/snapshots/`.

Имя версии содержит монотонную метку публикации и хеш содержимого. Время наблюдения хранится внутри снимка. Она записывается во временный файл и публикуется атомарным переименованием в той же директории. Читатель открывает последнее завершённое поколение. Отложенный ответ на более ранний запрос не откатывает полную версию. Хранятся два последних поколения каждого направления и источника. Для согласованного порядка времени нескольких процессов требуется одна временная шкала и файловая система с атомарным переименованием. CLI и сервер берут эксклюзивную блокировку по региону и источнику до начала запроса. Поэтому два параллельных ограниченных ответа объединяются по очереди. Рабочий каталог рассчитан на процессы одного хоста. Для блокировки используется служебный файл SQLite без строк каталога. ОС освобождает её при завершении процесса, в том числе аварийном. При занятой блокировке ожидание асинхронное, не более 40 секунд или времени переданного запроса. Чтение опубликованных JSON продолжается независимо от блокировки.

При полном ответе источника исчезнувшая строка удаляется из его выдачи. Если ответ OSM или Wikidata достиг известного лимита выборки, новые и изменённые строки дополняют предыдущие. Типовые ошибки HTTP, ответ Overpass с `remark` и CSV без ожидаемых колонок сохраняют последний успешный снимок. Повторный снимок с теми же полями обновляет время наблюдения без события об изменении отеля.

Индексы строятся при первом чтении направления. Поиск по ID использует карту ключей, следующая страница исходной выдачи — срез упорядоченного массива. Первое применение фильтра по области или подстроке просматривает строки одного региона; восемь последних комбинаций сохраняются для пагинации. При изменении исходных данных пересчитывается только затронутое направление. Загруженные регионы остаются в памяти до остановки процесса.

### Проверка масштаба

Из `apps/travel` выполните `node --expose-gc bench/catalog.ts`. По умолчанию команда создаёт 750 000 синтетических объектов в 16 временных файлах штатного формата, читает их реальным каталогом, проверяет пагинацию, текстовый фильтр, поиск по ID, удаление и повторную загрузку. Файлы удаляются по завершении; аргумент задаёт другое количество записей.

В одном контрольном запуске на Node 24 компактные исходные строки заняли 71,2 МиБ. Холодное построение индекса первого региона (46 875 записей) заняло 542 мс, 1 000 прямых вызовов пагинации по тёплому индексу — 1,90 мс суммарно, первый текстовый фильтр — 6,58 мс. Запись и перечитывание поколения с одним удалением и построение индекса этого региона заняли 949 мс. После открытия всех регионов RSS процесса составил 955 МиБ, пик всего прогона с генератором — 994 МиБ. Бенч использует локальные файлы с тёплым системным кешем; это замер слоя данных. Бинарники фотографий, запросы поставщиков, передача по сети и параллельные браузеры в него не входят.
