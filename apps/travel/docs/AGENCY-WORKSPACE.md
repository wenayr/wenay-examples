# Собственное агентство в сервисе

Откройте «Ещё → Моё агентство» или `/#agency`. Мастер создаёт рабочий кабинет: название, постоянный короткий адрес, контакты, цвет,
направления и источник туров. Это создание кабинета в сервисе, юридическая регистрация компании и договоры с поставщиками выполняются отдельно.
Действующий источник туров — TEZ TOUR Eesti. Его наличие в поиске не означает заключённый агентский договор или согласованную комиссию.

После сохранения доступны обзор, настройки и заявки. Имя и цвет применяются к интерфейсу, направления и источники учитываются сервером
до запросов к поставщику. Пустой выбор выключает соответствующий поиск. Настройки отзывов и графика либо миниматрицы применяются к карточкам.
Локальные предпочтения поиска остаются в браузере; профиль и заявки сохраняются на сервере между устройствами и перезапусками приложения.

«Открыть витрину» ведёт на `/a/короткий-адрес`: название, описание, деловые контакты, подбор туров и форма заявки именно этому агентству.
Форма возвращает номер обращения, а заявка появляется в кабинете владельца. Можно менять её статус и экспортировать обращения.
Текущая аудитория Site закрытая: ссылка открывается только пользователям с доступом к сайту. Кабинет не обещает публичного доступа без изменения аудитории.
Короткий адрес после создания постоянный, чтобы клиентские ссылки продолжали вести к своему агентству.

## Достоверные отзывы

Отзывы не генерируются и не копируются по похожему названию отеля. Серверный источник Expedia Rapid требует договора и ключей
`EXPEDIA_RAPID_KEY`, `EXPEDIA_RAPID_SECRET`. Они задаются владельцем размещения через серверное окружение, а не в форме агентства.
Администратор может сопоставить точный TEZ hotel ID с Expedia property ID и настоящей страницей этого объекта.
Перед сохранением нужно сверить имя и адрес в обоих источниках. Это сопоставление владельца, оно не является независимой проверкой.
Без доступа к API интерфейс честно показывает состояние подключения и доступные проверенные внешние страницы отзывов.
Подробный [контракт отзывов](HOTEL-REVIEWS.md) описывает источники, время проверки и ограничения.

## Хранение и доступ

Production Worker получает `BUCKET` от Sites R2. В `.openai/hosting.json` используется `"r2": "BUCKET"`, `"d1": null`.
Данные агентств — JSON-документы. Ценовой буфер остаётся ограниченным кэшем с TTL, SQL и дополнительная база для него не добавляются.
Владельца определяет доверенный заголовок Sites `oai-authenticated-user-id`; присланный клиентом owner/user ID не выбирает чужой кабинет.
Каждое чтение и изменение личного профиля или списка заявок привязано к этому владельцу.

Публичная проекция содержит только название, описание, деловые контакты, оформление, доступные направления и режим отображения.
В неё не входят owner ID, список клиентов, внутренний ID профиля, сопоставления отзывов и секреты поставщиков.
Реестр коротких адресов создаётся условной записью R2, затем записывается профиль. Витрина появляется только при согласованности обеих записей.
Если финальное сохранение прервалось, тот же владелец может повторить создание с тем же адресом и восстановить резерв.
Незавершённый резерв не публикуется и не переходит автоматически другому владельцу; освобождение такого адреса требует обслуживающей операции.
Это две условные записи, а не транзакция между объектами.

R2 ETag и версия профиля защищают от потери одновременных изменений. Конфликт возвращает HTTP 409, интерфейс предлагает загрузить актуальные данные.
Формы принимают только JSON с тем же origin, не более 16 KiB. Поля имеют серверные ограничения и допускают только известные значения.
В текущем кабинете до 1000 заявок и до 4 MB JSON; старые обращения не удаляются молча. Для дальнейшего роста нужен постраничный архив.
Перед открытием анонимной публичной аудитории нужен постоянный контроль частоты обращений; текущий Site сохраняет прежний закрытый доступ.

Managed preview использует отдельный Node-адаптер JSON в `.cache/agency-preview` и фиксированную тестовую identity.
Этот адаптер не импортируется production Worker и не даёт браузеру выбирать владельца заголовком.

## Проверяемые операции

- `GET/POST/PUT /api/travel/agency` — личный кабинет, создание и изменение с `revision`.
- `GET/POST /api/travel/agency/leads`, `PATCH /api/travel/agency/leads/:id` — заявки владельца и их статусы.
- `GET /api/travel/storefront/:slug` — ограниченная проекция витрины.
- `POST /api/travel/storefront/:slug/leads` — заявка выбранному агентству, ответ только `{accepted, reference}`.
- `agency=slug` в запросах каталога, матрицы и отзывов выбирает настройки витрины, но не даёт прав на её админку.
- `GET /api/travel/hotel-reviews?hotelId=tez:…` — отзывы с реальным статусом источника.

`test/agency.test.ts` проверяет изоляцию двух владельцев, восстановление после нового Worker, конкуренцию записей, безопасность проекции,
маршрутизацию клиентской заявки, ограничения форм, серверную политику источников и восстановление прерванного создания.
