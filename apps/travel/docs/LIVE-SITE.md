## Воспроизводимая сборка

Из корня GitHub checkout подготовьте самостоятельный Site source:

```bash
node apps/travel/scripts/prepare-site.mjs --destination /workspace/sites/wenay-travel-live
```

Скрипт копирует исходники только Travel, его точные package/lock, изображения, документацию и проверки. Node modules, локальные базы, runtime-данные и файлы окружения не копируются. Manifest и существующие правила игнорирования сохраняются. В Site checkout:

```bash
npm ci
npm run build
```

В исходном приложении та же сборка доступна как `npm run build:hosted`. Она создаёт Vite frontend в `dist/client` и самодостаточный Worker ESM в `dist/server/index.js` с default `{fetch}`. Все созданные frontend-файлы включаются в Worker, поэтому runtime не обращается к файловой системе и не зависит от внешнего checkout или node_modules. Размеры записываются в `dist/hosted-build.json`. Декодированный статический кэш ограничен 4 MiB.

Для managed preview используйте штатные `sites-preview start`, `status`, `stop` с этим Site checkout. `scripts.dev` запускает адаптер того же Worker.fetch; он принимает переданные daemon аргументы `--host` и `--port` и не выбирает другой порт. После изменения Worker bundle запущенный Node preview необходимо перезапустить штатным CLI.

Кабинеты агентств используют R2 binding `BUCKET`: подготовка source добавляет `"r2": "BUCKET"`, `"d1": null` в существующий manifest.
JSON-профили и заявки сохраняются в R2 с условной записью ETag. Авторизация владельца берётся из доверенной Sites identity.
Node preview отдельно хранит тестовые JSON-документы в `.cache/agency-preview`; фиксированная preview identity существует только в Node-адаптере.
Данные preview не копируются в Site и не подменяют production-авторизацию. Подробнее: [кабинет, витрина и заявки](AGENCY-WORKSPACE.md).

## Реальные операции Worker

Worker обслуживает `/api/travel/health`, `destinations`, `packages`, `package-hotel-search`, `package-calendar`, `package-trends`, `package-matrix`, `package-gallery`, `package-compare`, `package-recheck`, личный `agency`, tenant `storefront/:slug` и `hotel-reviews`. Health перечисляет возможности runtime, а не подтверждает доступность предложений поставщика.

Поиск имени выполняется сервером по индексу текущего окна TEZ. В цене сохраняются его маршрут, ночи, гости, валюта и источник. Пагинация поиска выдаёт ограниченную порцию, не весь каталог. Проверенные метаданные Хургады, Шарма и Родоса остаются доступны без тарифа; у такого отеля отсутствует ценовое поле и предлагается проверить матрицу. Это не глобальная гостиничная база и не обещание наличия тура.

Обычный кэш наблюдений действует 120 секунд. Ручной `refresh=1` действительно обходит сырой кэш. `retryAt` обозначает автоматическую паузу между запросами. Если обновление не удалось, прежняя цена сохраняет исходное время и `source.stale=true`; ячейка не считается подтверждённой. Polling интерфейса приостанавливается для неактивной вкладки и закрытого поиска/окна.

Манифесты местоположений и фотографий статически включены в сборку. Область карты выбирает источники автоматически; Анталия дополнительно использует ленивое разрешение официального региона и гостиничных метаданных. Ни цены, ни координаты отсутствующих предложений не имитируются. Общий cooldown учитывает Retry-After источника. Web Crypto SHA-256 сохраняет прежние идентификаторы тарифов. Используются опубликованные browser-compatible экспорты `wenay-common2/client`. В Worker нет Node fs, SQLite, raw TCP и динамической генерации кода. R2 предназначен для профилей агентств и заявок; ценовой буфер остаётся без базы данных.

Полный прежний Node backend остаётся в репозитории. Операции других модулей, не подключённые к этому Worker, возвращают понятный HTTP 501 с фактическим перечнем возможностей. Цены и успешные ответы для них не имитируются.
