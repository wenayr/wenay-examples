## 1. Общие условия исполнения

### 1.1. Окружение

- Node ≥ 22.12, npm. Команды приложений выполняются из каталога приложения: `cd apps/<name> && npm run <script>`.
- Оболочка — Git Bash. Пути в скриптах — через `node:path`, без жёстких `C:\`.
- Порты приложений (из точек входа, проверено 11 сентября): pizzeria 3500, органайзер пиццерии 3600, hosting 3700, catalog 3800, support 3810, documents 3811, metering 3812, crm 3813, booking 3814, forms 3815, monitoring 3816, content 3817, approvals 3818. Тесты используют порт 0 и временные каталоги — их запускать можно всегда.
- Docker есть не всегда. Перед любым `test:docker`/`*-live-check` выполнить `docker info`; при ошибке — пометить «Docker недоступен, не проверено» и не считать это падением.
- Python 3 нужен только `documents` (отдельный обработчик). Проверить `python3 --version` или `python --version`.

### 1.2. Порядок приложений

Везде, где перебираются приложения, используется этот порядок (по времени появления, затем по зависимостям):

```
pizzeria hosting support documents metering crm booking forms monitoring content catalog approvals
```

### 1.3. Что считается «прошло»

- `typecheck`: `npx tsc --noEmit` завершился с кодом 0.
- `test`: `npm test` завершился с кодом 0 и в выводе есть строки `PASS`.
- `build`: `npm run build` завершился с кодом 0 и создан `public/index.html`.
- Любое «прошло» в отчёте сопровождается командой и хвостом вывода (последние 5–10 строк).

### 1.4. Коммиты

Сообщение — на русском, повелительное наклонение, первая строка до 72 символов, затем пустая строка и 1–5 строк сути. Каждая задача даёт ровно один коммит (кроме G01, где их несколько, и Q03/Q04, где один коммит на приложение). Все коммиты заканчиваются строкой:

