# Экран, голос и работа между устройствами

Подготовлено 10 сентября 2026: common2 2.21.1 / react2 3.5.0. Наличие методов браузера, синтетический canvas и protocol fixtures не означают прохождение настоящей приёмки.

## Среда

Использовать два физических устройства и разные разрешённые аккаунты. Перед запуском записать дату, npm-версии, устройства/ОС/браузеры, адреса страниц, authority/serving nodes, тип сети, источник экрана и микрофон. Пароли/токены в отчёт не включать.

Для capture нужен защищённый контекст. HTTP localhost подходит для локальной проверки; обычный HTTP по сетевому IP не равнозначен localhost. Доступность показа экрана зависит от браузера. Источник выбирает пользователь, разрешение требуется для каждого показа. [MDN: экран](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia), [MDN: микрофон](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

Для второй машины сначала определить доступную пользователю среду и доверенный HTTPS-адрес. Не подставлять адрес из посторонних задач и не отключать проверку сертификатов. Демонстрационные аккаунты использовать в ограниченной тестовой среде.

Runtime уже поддерживает `SERVICE_HOST`, `SERVICE_PORT`, `SERVICE_PUBLIC_URL`, `SERVICE_CORS_ORIGINS`. PUBLIC_URL не создаёт TLS/прокси: прокси передаёт маршруты HTTP и `/socket.io/` с WebSocket upgrade; published origin без path-prefix. Каждый serving node имеет отдельный стабильный ID и достижимый origin. `SERVICE_UPSTREAM` задаёт связь с authority отдельно. Разрешить точный origin UI, а не все origins. Секреты передать вне отчёта, один каталог данных принадлежит одному authority. Контракт есть в установленном common2, `doc/SERVICE-PUBLIC-ADDRESS.md`.

## Последовательный сценарий

1. **Доска.** A и B входят разными аккаунтами и видят общую заметку. A двигает её и отменяет: B видит временное движение, сохранённая позиция не меняется. Затем подтверждает движение: позиции сходятся. Повторить в обратную сторону. Присутствие не открывает доступ к личным задачам.
2. **Настоящий экран.** A и B открывают экранную комнату. A выбирает тестовую вкладку/окно с несекретным содержимым. Изменить заметный текст/цвет внутри источника; на B должны быть видны изменения, а не один кадр. Текущая реализация: два участника, один экран, до 5 кадров/с, без звука и записи экрана.
3. **Остановка.** Остановить кнопкой приложения, затем повторить и остановить штатной кнопкой браузера. Источник освобождён, у B показ прекращается, новый запуск требует нового выбора. Закрытие панели также освобождает источник.
4. **Разрыв.** Оборвать соединение A, восстановить; старый захват не возобновляется автоматически, новый показ запускается явно. Отдельно проверить уход/возвращение B, отсутствие старого присутствия и кадров прежнего поколения.
5. **Настоящий голос.** В разговоре A записывает короткую согласованную фразу, останавливает, прослушивает и отправляет. B прослушивает доставленное сообщение. Проверить удаление черновика, повторную запись, предел 12 секунд, отказ в разрешении и закрытие панели во время записи. Индикатор микрофона должен погаснуть; успешный RPC сам по себе этого не доказывает.
6. **Сохранение и права.** Повторно открыть разговор на B: текст/голосовое доступны из истории. Владелец исключает B из тестового разговора: новое чтение и сохранённый фасад/вложение больше не дают доступ. Исключение из разговора не равно отзыву доступа ко всему органайзеру; экранную комнату проверять через её собственную границу доступа.
7. **ИИ без оплаты.** Проверить помеченный тестовый путь текст → предложение → подтверждённые обычные задачи. Это не проверка распознавания. Платный провайдер и автоматическое повторение неизвестного внешнего результата отключены.

## Масштабирование проверять отдельно

При доступных адресах: один authority, два serving node существующим `start:organizer:node`, клиенты действительно подключены к разным узлам. Зафиксировать адреса соединений; остановить один узел во время работы, проверить восстановление и отсутствие дубликатов. Затем восстановить authority из архива. Потерю authority не выдавать за доказанный автоматический переход права записи.

Чат/экран через authority не доказывают распределение медиатрафика между serving nodes. Независимые заведения с разными writers — другая топология. Реальные VM/Kubernetes для этого шага не нужны; бюджет RAM 1–2 ГиБ, максимум 3, запуски последовательно.

## Протокол результата

Для каждого пункта: «пройдено / не пройдено / не запускалось», среда, ожидаемое/наблюдаемое и ошибка. Время восстановления — от разрыва до первого подтверждённого нового действия. Для видео отметить меняющееся изображение и прекращение кадров, для голоса — реальное прослушивание. Не прикладывать личное содержимое или секреты.

Новый сбой сначала локализовать: приложение, условия браузера/сети или библиотека. В `doc/library-tasks` отправлять минимальное воспроизведение только общей библиотечной проблемы; сообщения UI и адреса конкретного стенда остаются приложению.
