# План после 0.9.0

**Актуальный порядок новых работ:** [стратегия развития библиотек через приложения](LIBRARY-STRATEGY.md). S1/S2 выполнены на common2 2.19.0/react2 3.3.0: [движение карточек и свободная доска](changes/collaboration-s2.md). Следующий срез — S3, экран для двух участников без записи. Затем размещение собственных проектов, масштабирование, мессенджер и голос/ИИ. Этот порядок заменяет прежний приоритет расширения хостинга; достигнутые результаты и незавершённые проверки ниже сохраняются.

Цель: превратить проверенные пиццерию и самостоятельный органайзер в удобную основу следующего приложения на опубликованных common2/react2. Сохраняем точные версии 2.19.0/3.3.0, пока сценарии не требуют нового релиза.

Уточнение приоритета: пользователь поручил начать полноценный [хостинг VM/LXD/Kubernetes](HOSTING-PLAN.md). Первый управляющий API создан в `apps/hosting`. Этапы 2–3 ниже сохраняются как дальнейшие улучшения органайзера и не блокируют хостинг.

## 1. Завершить применение hooks в обзоре сети — выполнено в 0.10.0

- Каждая строка заведения владеет своей сессией через общий useServiceSession/useOwnedClient и читает revenue через useClientStore.
- Удалить массив вручную созданных клиентов и список ручных подписок. Агрегировать только доступные актуальные строки, сохранять явный охват.
- Передать pending/error масштабирования useAsyncAction через существующий адаптер. Смена заведения/токена не должна показывать старый результат или запускать действие от предыдущего пользователя.
- Отменять незавершённые чтения при уходе со страницы; различать загрузку, отсутствие доступа и потерю связи.
- Проверки: typecheck, обе сборки, настоящий сетевой сценарий; браузер владельца с несколькими заведениями, обновление доступа, logout и масштабирование.
- Исправить устаревшее описание секундного опроса прав в NETWORK.md. Результат этапа — небольшой законченный выпуск и отчёт.

Результат: hooks применены, typecheck, обе сборки и сетевой тест проходят. В браузере двух заведений проверены живая выручка, отзыв/возврат прав без обновления страницы, refresh, logout и переключение во время масштабирования. [Подробный отчёт](changes/0.10.0.md).

## 2. Доска с большим количеством задач — отложено за хостингом

- Подготовить воспроизводимые данные длинной колонки и узкого экрана, не менять пользовательский архив.
- Проверить автопрокрутку по двум осям при удержании у края, остановку после drop/Escape и смены прав, ручку клавиатуры, фокус после replay и действие фильтров.
- Проверить две одновременно открытые сессии: устаревшая ревизия отклоняется, успешное действие видно обеим, повтор не создаёт дубликат.
- Реальные дефекты приложения исправлять здесь; дефекты библиотечного механизма описывать воспроизведением и ждать опубликованный patch. Реальное touch-устройство считать отдельной проверкой, если его нет в среде.

## 3. Проверить переносимость на минимальный новый сервис

- Сделать минимальный пример произвольной работы: definition, роли, одна команда, защищённое представление, host и React-клиент.
- Импорты общего кода — из публичных npm entrypoints; подключения к пиццерии только как необязательные адаптеры предметного модуля.
- Описать создание нового типа клиента и ролевого фасада; показать реальный второй процесс чтения и восстановление клиента.
- Сравнить остаточную обвязку двух продуктов и шаблона. Выносить только повторяемое поведение с ясным владельцем ресурса, не создавать универсальные формы заранее.

## 4. Следующий боевой пример

После первых трёх этапов — пример аренды экземпляров приложений из ROADMAP: реальный запуск, readiness, остановка, обновление/откат и масштабирование. Сначала использовать опубликованные process/host ресурсы; топологию, лимиты и роли держать предметным кодом. Межмашинное размещение и HA не обещать без отдельного исполняемого сценария.

Каждый этап заканчивается работающим результатом, соответствующими проверками и отдельным выводом о пользе библиотек. Переход к следующему этапу не означает автоматическую публикацию сайта или npm-пакета.
