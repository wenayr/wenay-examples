# Правила приёмки каталога SaaS

Обновлено 11 сентября 2026, задача R02 [плана 3](PLAN3-TASKS.md). Здесь описано, **как** принимается работа. **Что** принято по каждой задаче, написано в столбце «Статус» [очереди из 80 задач](SAAS-EXAMPLES-BACKLOG.md) — это единственный источник состояния; прежняя таблица задач из этого файла удалена, чтобы два списка не расходились.

## Словарь состояний

| Состояние | Что означает |
| --- | --- |
| выполнено | Приёмка строки пройдена целиком. Будущие улучшения возможны, но строка их не ждёт |
| выполнено с границей | Приёмка пройдена, и рядом названо ограничение, за которое она не выходит (внешний провайдер не настроен, модель не запускалась, замер сделан на одной машине) |
| частично | Строка закрыта не полностью; рядом названо, что именно осталось и чем это проверить |

Групповые контрольные точки G0–G6 не закрываются автоматически по наличию приложения: они требуют полной приёмки всех строк своей группы.

## Обязательный набор для продуктовой строки

Финальная строка каждой продуктовой группы (H08, D08, P08, C08, R08, F08, M08, W08) включает набор из раздела [«Общая приёмка каждого продукта»](SAAS-EXAMPLES-BACKLOG.md#общая-приёмка-каждого-продукта) очереди: завершённые пути всех ролей и серверная изоляция; воспроизводимая установка точных зависимостей; сохранение после рестарта, повтор команды, конкурирующее действие, отзыв доступа и восстановление соединения; реальная заявленная топология с опубликованными ограничениями и измерениями; размещение через хостинг с readiness, обновлением и откатом; реалистичные демоданные, пустые и ошибочные состояния, клавиатура и узкий экран; README, карта фасадов, рецепт расширения и отчёт о повторном использовании.

Реальные модельные запросы, платежи и тяжёлая инфраструктура по этому плану не запускаются. Непроверенная внешняя интеграция помечается отдельно и не прячется под успешным тестом имитатора.

## Копия и восстановление данных

Общая приёмка продукта дополнена строкой: холодная копия каталога данных снимается и восстанавливается в новое место, после чего сервис запускается на восстановленных данных и отдаёт прежние записи. Инструменты — `scripts/backup.mjs` и `scripts/restore.mjs`, живая проверка приложения — `npm run test:backup`. Состояние по каждому приложению — колонка «Копия» в [STATUS](STATUS.md); подробности и границы — [отчёт](reports/backup-restore.md).
