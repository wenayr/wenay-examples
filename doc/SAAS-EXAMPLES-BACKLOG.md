# Очередь реализации SaaS-примеров

Дата: 10 сентября 2026. Основание: [стратегия каталога](SAAS-EXAMPLES-STRATEGY.md). Все задачи ниже запланированы; существующие механизмы считаются материалом для повторного использования, а не основанием автоматически отмечать новую приёмку выполненной.

## Порядок выполнения

1. B01–B04: инвентаризация, критерии, карта фасадов и сценариев.
2. B05–B08 вместе с H01–H03: только основа, необходимая первому реальному продукту.
3. H04–H08: закончить поддержку целиком, включая ИИ без оплаты, размещение и отказы — G1.
4. D01–D08: документы, второй потребитель общих блоков, Node/Python — G2.
5. P01–P08: учёт потребления двух продуктов, публичный API и тестовые тарифы — G3.
6. C01–C08, затем R01–R08: CRM и бронирование — G4.
7. F01–F08, M01–M08, W01–W08: формы, мониторинг, контент — G5. Пересмотреть этот порядок по результатам G2, сохранив критерии полезности из стратегии.
8. K01–K08: упаковка начинается с первого примера и завершается испытанием нового SaaS из чистого каталога — G6.

Всего 80 задач. Для каждой строки результат проверяемый; таблицы обозначают небольшие этапы, а не единую задачу «написать всё приложение». Внутри группы зависимость по умолчанию — предыдущая строка, если в столбце не указано иное. Зависимость от другой группы указывается явно. При нехватке библиотечного API остаётся точное воспроизведение и открытая задача; фиктивный адаптер не закрывает боевую приёмку.

## Общая приёмка каждого продукта

Финальная строка каждой продуктовой группы включает этот обязательный набор:

- Завершённые пути всех ролей, самостоятельный запуск, серверная изоляция команд/чтения/подписок/файлов/заданий.
- Воспроизводимая установка точных npm-зависимостей и запуск без внешних секретов; имитации подписаны в UI и документации.
- Сохранение после рестарта, повтор команды, конкурирующее действие, отзыв доступа, разрыв соединения и восстановление UI.
- Реальная проверка заявленной топологии; процессы действительно обслуживают запросы или задания. Публикуются ограничения записи/владения и измерения памяти, задержек и восстановления.
- Размещение через существующий хостинг, readiness, обновление, проверка совместимости данных и откат/восстановление с описанными границами.
- Реалистичные демоданные, пустые/ожидающие/ошибочные состояния, клавиатура, узкий экран, визуальная проверка основных экранов.
- README, карта фасадов, рецепт расширения для ИИ, отчёт о повторном использовании и подтверждённых потребностях библиотек.

Реальные модельные запросы, платежи и тяжёлая инфраструктура не запускаются по этому плану автоматически. Локальные профили последовательные, целевые дополнительные затраты 1–2 ГиБ, максимум 3 ГиБ. Непроверенную внешнюю интеграцию помечаем отдельно; она не должна скрываться под успешным тестом имитатора.

## Формат отдельного рабочего задания

При начале строки исполнитель получает: ID и цель, входные выполненные зависимости, пользовательский путь каждой роли, разрешённые каталоги, существующие публичные механизмы, результат и проверки из строки, лимит ресурсов и запрет платных вызовов. После работы оставляет изменённые файлы, результаты проверок и остаточные ограничения. Лёгкую изолированную работу можно делегировать, только если её постановка и проверка дешевле самостоятельного выполнения; архитектура зависимых фасадов остаётся согласованной.

Новая библиотечная потребность оформляется отдельным файлом с точными версиями, воспроизведением/двумя потребителями, ожидаемой общей гарантией и проверенными альтернативами. Неподтверждённая идея остаётся в отчёте примера и не выдаётся за необходимую доработку common2/react2.

## Что не включено в ближайшую очередь

Полный marketplace, бухгалтерия/налоги, универсальный no-code builder, собственный почтовый сервер, новая Slack/Notion-копия, видеоконференции с SFU, полноценный Kubernetes control plane и обучение собственной модели. Эти продукты способны поглотить работу без пропорционального прироста повторяемых SaaS-механизмов. Возвращаемся к ним при конкретном сценарии и потребителях; уже сделанные доску/чат/хостинг продолжаем использовать и проверять.
