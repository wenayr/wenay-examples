# Начальные контракты wenay-shell

Версия 0, 27 сентября 2026. Проектные границы для [исполняемого плана](SHELL-EXECUTION-PLAN.md).
Это собственный небольшой контракт композиции модулей, не описание уже существующих
функций wenay-common2/react2. Транспортные, conversation, AI и store типы повторно не объявляются.
Root принимает изменения общих границ; автор конкретной фабрики выводит её результат из реализации.

## 1. Пять разных понятий

| Понятие | Пример | Владелец |
| --- | --- | --- |
| Module definition | `video`, `cad`, `chat`, `text` | Пакет функциональности; не экземпляр пользовательского проекта |
| Application profile | `assistant`, `video-studio`, `design-studio` | Композиция модулей и начальный экран продукта |
| Section / subsection | `video.projects` → `video.assets`, `video.edit`, `video.export` | Объявленная модулем навигация, parent-child дерево |
| View | `video.editor`, `chat.conversation` | Рабочее представление, порядок/расположение блоков |
| Block | `video.preview`, `video.timeline`, `video.inspector` | Подключаемая поверхность одного представления |

Document/job/artifact являются серверными предметными сущностями и не наследуют эту
иерархию навигации. Один документ может открываться несколькими view, одно view —
показывать несколько ссылок на документы. Раздел «Видео» существует без чата.
Профиль `assistant` может сделать чат главным; профиль `video-studio` делает главным видео.

## 2. Metadata первой пробы S00.04

| Объект | Минимальные поля и ограничения |
| --- | --- |
| Module | `id`, `version`, `contractVersion: 1`, `requires`, коллекции `sections`, `views`, `blocks` |
| Section | `id`, `title`, необязательный `parentId`, `viewId` для открываемого экрана |
| View | `id`, `title`, список `blockIds`; предметный renderer пока не входит в headless metadata |
| Block | `id`, `title`, поддержанные `platforms`: web/mobile/desktop/cli |
| Profile | `id`, `moduleIds`, порядок корневых `sectionIds`, `startSectionId`; chat не обязательное поле |

Module ID — непустой lowercase ASCII slug. Contribution ID имеет пространство имён
своего модуля: `video.assets`, `video.editor`, `video.preview`.
ID уникален в своей категории; строка с пробелом, traversal или неверным namespace отклоняется.
Родитель subsection принадлежит тому же module. Ссылки view/block должны разрешаться
в доступных definitions. Межмодульная ссылка требует явной зависимости, включённой в профиль.
Дубли module/section/view/block/profile ID, неизвестная ссылка и cycle дают точную ошибку.

`contractVersion` в v0 проверяется на точное поддержанное значение. Не писать свой
semver-range resolver: полноценная совместимость/миграции — S03.01/S03.07.
Metadata реестра не выдаёт server permission. `platforms` означает наличие представления,
а не право пользователя выполнять команду или наличие реального video encoder.

## 3. Фасад композиции

Предлагаемая фабрика S00.04 — `createComposition({modules, profiles})`.
Возвращаемый тип выводится как ReturnType; общий input-контракт нужен настоящему
семейству modules. Выход — намеренный read-фасад `view`, например:

- найти определение модуля/раздела/view/block/profile по ID;
- получить дерево разделов выбранного профиля, сохраняя объявленный порядок;
- разрешить маршрут profile + section в view и его blocks для указанной платформы;
- вернуть явный unsupported/error для отсутствующей возможности.

Агент может уточнить имена read-функций в своей области, сохранив смысл и записав
фактический контракт в README. Другие агенты первой волны на эти имена не зависят.
Динамические server installs, jobs, scopes и React components не помещаются в эту пробу.
При появлении server instance lifecycle он создаётся отдельной фабрикой с явными deps.

## 4. Библиотечные границы

- Native service host/client, conversation host/client и replay берутся из публичных exports.
- Нельзя заменить существующий receipt собственным Map и объявить native retry проверенным.
- Структуры message blocks/tool events/state сохраняют типы библиотеки.
- React использует публичный react2 hook и native common2 state; существующий hook
  нельзя молча заменить локальной подпиской, скрыв ошибку совместимости.
- В headless composition обычные чистые функции допустимы: библиотека применяется
  там, где есть её механизм, без искусственных обёрток ради количества импортов.
- Известный разговорный lifecycle guard можно перенести минимальным адаптером с ID
  библиотечной проблемы и воспроизводимой проверкой; новые ограничения не скрывать.

## 5. Постоянные данные и исполнение

Scope ресурса: server connection + account + workspace + project + module instance + document.
Переключение контекста закрывает ресурсы старого поколения. Выдача результата повторно
проверяет текущий ACL; layout/cache/видимость кнопки не являются проверкой доступа.

Долговечный job принадлежит серверу/модулю. View close освобождает UI, cancel — отдельная
предметная операция. При disable модуля новые команды запрещены; accepted job работает
на закреплённой версии либо отменяется по своему контракту. Данные сохраняются.

Состояния интерфейса минимум различают loading/ready/unavailable/denied/error.
Состояния выполнения берутся из actual job/AI API; `uncertain` внешнего действия
не переименовывается в бесплатный отказ. ID/payload повторяемого запроса сохраняются.

Вложения и exports имеют владельца, source revision, MIME/size и реальный storage reference.
Исходная CAD-сцена не сериализуется в каждом сообщении. Видео — проверяемые медиа-байты,
а его editable project отдельно хранит ссылки/параметры. Большие данные не становятся React state.

## 6. Компоновка

Профиль задаёт default layout и присутствие помощника. Core умеет расположить sidebar,
main view и auxiliary blocks; core не решает, что main обязательно является conversation.
Для одного view доступны chat-first/workspace-first представления и изменение размеров.
Мобильный клиент переключает рабочие области, сохраняя выбранный документ.

Block lifecycle задаёт mount/update/close на разрешённом документном фасаде.
Конкретная сигнатура фиксируется в S03.02 на реальных text/CAD/video потребителях;
сейчас нельзя заранее создать многостраничный plugin SDK с неиспользуемыми hooks.
Lazy imports разделяют Node/browser/native границы; CLI не загружает React/Three/Canvas.

## 7. Примеры составов для приёмки

| Профиль | Модули | Начальный раздел | Проверяемое свойство |
| --- | --- | --- | --- |
| Assistant | chat, text | chat.conversations | Привычный список/диалог; документ открывается в рабочей области |
| Video studio | video, text | video.projects | Установка/наличие chat не требуются; подразделы материалов/монтажа/экспорта |
| Design studio | cad, text, необязательный chat | cad.projects | Canvas и свойства главные; помощник может быть вспомогательным блоком |

В S00.04 эти записи — metadata fixtures для проверки композиции. Они не считаются
работающими CAD/video модулями. Настоящие результаты принимаются в S05 и S11.

## 8. Изменение контракта

Исполнитель сообщает root: почему текущего входа не хватает, минимальное изменение,
затронутые потребители, миграция старых данных/метаданных и проверка.
Root фиксирует решение и версию, затем назначает изменения владельцам файлов.
Нельзя просто заменить общий файл одновременно в двух задачах или заставить потребителя
угадывать новый формат. Переход с v0 на реальный SDK опирается на два работающих модуля.
