# Этапы, зависимости и приёмка, 26 сентября 2026

План продолжает [стратегию Q01–Q10](../STRATEGY-2026-09.md).
Он связывает задачи устойчивыми ID и отделяет написанный код от доказанного результата.
Состояние обновлено после общей проверки графической ветки и повторного UI review.
Прерванные прогоны не засчитаны; ниже указаны только завершённые проверки.

## Значение статусов

- **Реализовано**: код и описание результата существуют; это не свидетельство исполнения.
- **Проверено**: перечисленные проверки выполнены на данной ветке; частичная проверка называется частичной.
- **Принято**: выполнены критерии этапа, включая пользовательский сценарий и необходимые ограничения среды.
  Частичная приёмка допускается только с явно названной границей; она не закрывает весь этап.
- **Ожидает**: работы или доказательства ещё отсутствуют. Прерванный прогон не считается пройденным.

У каждой задачи три независимых состояния. Сборка не заменяет сценарий, fixture не заменяет live,
а результаты исходной ветки не принимают отсутствующий в ней графический код.
Для переноса в main необходим успешный `npm run check:all` итогового состояния согласно [правилам](../CODE-RULES.md).

## Регулярное упрощение с сохранением смысла

Оптимизация следует после проверки поведения и UX соответствующей границы.
Она не заменяет приёмку и не даёт оснований удалить предметную проверку ради меньшего кода.

| ID | Предшественники | Действие и критерий |
| --- | --- | --- |
| OPT-G | G01, G02 (локальные сценарии) | Проверить фасады/зависимости календарей, одноразовые helper и дубли; небольшое упрощение либо мотивированный вывод «не требуется»; повторить затронутые tests и жесты |
| OPT-API | Q04, Q05 (backend и пользовательские границы) | По двум потребителям найти минимальный общий адаптер, сохранить tenant/scopes/revoke/IO; повторить отрицательные ACL и replay сценарии |
| OPT-UX | Q07-M, Q07-D, соответствующий Q08 | Удалить лишнее состояние, ветвления и дубли после UX приёмки; повторить смену выбора, cancel, stale response и permissions |
| OPT-REUSE | Q10 | По автономной копии удалить доказанно лишнюю обвязку; сохранить public npm API, reconnect/replay и предметные инварианты |

Каждый checkpoint фиксирует исходный контракт, конкретное упрощение, затронутые места и повторную проверку.
Отсутствие безопасного упрощения — допустимый результат аудита. Для изменения общего механизма сначала
проверить публичные API; библиотечный дефект оформляется repro, не локальной подменой npm.
После смысловой правки старый PASS не переносится: повторить необходимые проверки на новом коде.
Итоговый G03 должен подтверждать состояние после OPT-G; если checkpoint изменяет код после gate, gate повторяется.
