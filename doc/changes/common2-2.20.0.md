# Принятие common2 2.20.0

10 сентября 2026. Оба приложения и lock-файлы обновлены до точного npm `wenay-common2@2.20.0`. `wenay-react2@3.3.0` сохранён. Использованы только публичные API опубликованного пакета. Платных запросов не было.

## Что принято

| Пункт | Изменение потребителя | Проверка |
| --- | --- | --- |
| H3 | Docker-агент передаёт `SERVICE_PUBLIC_URL` из зарегистрированного gateway отдельно от порта слушателя и CORS | Реальные organizer и pizzeria: deploy/update/rollback через service RPC, Store и SC1 screen/chat; один URL, сохранённые сообщения и AI receipts |
| M1 | PCM-путь приложения сохранён; исправление проверено опубликованным `createAudioSource` | Прежний repro с `--expect-fixed` проходит: старый отложенный MediaRecorder chunk не попадает в новый запуск |
| A1 | `openAiCheckpoint` подключает `openFsReplayStorage` к `AiRunHost.initial/persistence`, UI показывает `run.recovery` | Перезапуск/дедупликация/изменённый запрос, сохранённые input/approval, повреждённый последний append, write-before-effect, отзыв прав и явное recovery; отдельный процесс принудительно завершён после тестового эффекта |

H3/M1/A1 закрыты в интеграции примеров. H1/H2 common2 и R4 react2 остаются предложениями; новых библиотечных дефектов эта проверка не подтвердила. Исходный [отчёт S3–S8](complete-strategy.md) сохраняет исторические ограничения 2.19.0; актуальный статус — здесь.

## Размещение

`SERVICE_PUBLIC_URL` задаётся из доверенного адреса окружения; входящие Host/X-Forwarded заголовки его не определяют. Runtime использует новую настройку напрямую, без копии host lifecycle. В live-check загружается настоящий descriptor каждого приложения, а общая organizer-поверхность проверяется одинаково.

Оба продукта сохранили задачу, conversation/message ID и ID завершённого ИИ-запуска через две замены образа. Повтор одинакового ИИ-запроса после замены вернул прежний run. Проверены открытие/закрытие screen resource и команды чата через gateway. Дополнительно исходный клиент и открытый chat resource удерживаются через rollout: Store сохраняет объект, ресурс получает новое поколение и снова читает историю.

Браузерная приёмка размещённой пиццерии: вход owner, открытие органайзера, сохранённый разговор, завершённое тестовое предложение, подтверждение обычной задачи. Ошибок/предупреждений в консоли этой вкладки не было. Это закрывает прежний блокер размещённого UI. Захват настоящего экрана и микрофона по-прежнему требует отдельной ручной проверки; новое разрешение устройств не запрашивалось.

## Долговечность ИИ

Архив находится в `SERVICE_DATA_DIR/chat/ai/runs.replay`. Синхронный port сохраняет полный checkpoint через публичный replay storage с Node V8 codec и fsync перед подтверждением. Это один локальный writer; приватный архив содержит исходные входы. Он не публикуется через HTTP/RPC. Сохраняются прежние лимиты приложения: один активный запуск, до 100 запусков в памяти. Нужные для большого сервиса хранение/retention и распределённое владение не заявлены этим лёгким примером.

После рестарта незавершённый run сохраняет состояние и признак recovery. UI показывает требование сверки вместо бесконечного индикатора работы. Обычная отмена доступна пользователю. Server-only `recovery` не включён в RPC-фасад; resume/settle предназначены для доверенного адаптера, который проверяет фактический исход провайдера. Автоматического повторения run нет, включая queued. Готовые предложения по-прежнему сохраняются в conversation facts и применяются обычной идемпотентной командой задач.

Проверка отдельного процесса: fixture записал один локальный эффект, процесс завершён до результата, новый host прочитал running/recovery без нового эффекта, сервер явно сверил файл и вызвал settle. Это проверка неопределённого внешнего исхода без ИИ/оплаты, не обещание exactly-once произвольного провайдера.

Старые завершённые предложения из 2.19.0 остаются в conversation journal. Старые in-memory run, которые до обновления не сохранялись, восстановить задним числом невозможно.

## Воспроизведение

В `apps/pizzeria`: `npm run typecheck`, `npm test`, `npm run build`, `npm run build:organizer`. В общий test входят A1 и M1; отдельно — `npm run test:ai-persistence` и `npm run repro:media-generation -- --expect-fixed`.

В `apps/hosting`: `npm run typecheck`, `npm test`, `npm run build`, `npm run prepare:products`, `npm run test:public-address`. Для второго продукта в PowerShell: `$env:HOSTING_APP_KIND='pizzeria'`, затем тот же тест. После проверки удалить эту переменную перед запуском organizer. Исторический `repro:public-address` — alias положительного теста, теперь должен проходить. `test:stateful` отдельно сохраняет REST backup/readiness-сценарий.

Все общие тесты и три production-сборки прошли. Маленькие Docker-стенды выполнялись последовательно, приложение 256 МиБ/0,5 CPU. Во время проверки WSL наблюдался около 0,7 ГиБ; это снимок, не измеренный максимум всей системы. Тестовые контейнеры/тома убраны, пользовательский контейнер оставлен. VM, Kubernetes и локальные модели не запускались. Сохранились прежние предупреждения Vite о размере JS/config loader.

Остаток: H1/H2/R4 оценивать по отдельным постановкам; ручные устройства/межмашинная сеть и подключение реального провайдера — отдельные условия приёмки. Текущий выбор пользователя остаётся «без платных запросов».
