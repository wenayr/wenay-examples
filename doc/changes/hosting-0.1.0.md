# Хостинг 0.1.0 — первый срез управляющего сервиса

Создан отдельный `apps/hosting` с собственными package.json, npm lockfile, проверкой типов и интеграционным тестом. Он не импортирует backend пиццерии или исходники lanaFour. Взяты сценарии LXD и версионных деплоев из lanaFour, а связь клиентов, фасады, авторизация команд, receipts, replay и архив предоставляет публичный common2 2.18.1.

Реализованы пять ролей, проекты и окружения с назначенным агентом, неизменяемые версии по OCI digest, deploy/rollback с optimistic concurrency, очередь, захват операции и ограниченный отчёт агента. Проекции различаются для людей и агентов и фильтруются по проекту. Секреты аккаунтов не записываются в состояние приложения.

Проверки: `npm run typecheck` и `npm test` проходят. Интеграционный сценарий использует настоящий HTTP/RPC host и семь клиентов: серверный запрет мутаций наблюдателя/агента, чужой проект, неверный агент, неизменяемость версии, неподтверждённый rollback, неверный digest, устаревший отчёт, повтор requestId, live view, два конкурирующих автора, восстановление архива и receipts после перезапуска. Подтверждено сохранение действующей версии при ошибке и переход между версиями по отчётам тестового агента.

Внешний провайдер в этом тесте имитируется. Реальное создание VM, установка среды, lease/fencing, worker processes, Kubernetes и интерфейс ещё не реализованы. На текущем Windows-хосте WSL не установлен, docker/kubectl/helm/LXD не найдены; среда реального Linux-теста уточняется. Тест не обращается к рабочим серверам lanaFour.

Польза библиотеки уже видна: новый продукт описывает предметное состояние, доступ и операции, не копируя transport/reconnect/replay, REST-router и файловый журнал. Новых библиотечных блокеров этот срез не выявил. Достаточность runtime для длительных внешних действий будет проверена на этапе исполнителя; успешная RPC-команда не приравнивается к exactly-once установке VM.
