# Хостинг 0.2.0 — OCI-исполнитель и панель

Общий профиль приложения теперь содержит port, healthPath, CPU и RAM. Он не зависит от языка: добавлены примеры Node.js и Python. Релиз закрепляет финальный образ по digest. Микросервисная связь исполнителя с управляющим API полностью проходит через публичный common2.

Добавлены Docker Engine resource, отдельный agent entrypoint, детерминированный ID контейнера, проверка владельца/образа, readiness, отчёт адреса, восстановление после неоднозначного IO и локальный lock. Панель на react2 использует useOwnedClient/useClientStore/useServiceCommands/useAsyncAction; позволяет создавать проекты, окружения, версии и заявки, смотреть историю и отправлять rollback. Дополнительные поля совместимы с архивом 0.1.0.

Проверено: typecheck, build; сервисный интеграционный тест, Docker HTTP contract test, настоящий RPC между агентом и control API с Docker fixture. В браузере пройдены login, создание проекта/окружения/релиза и постановка заявки. Консоль без ошибок. Тестовые данные браузера используют `example.invalid` и не считаются развёрнутым приложением.

Docker Desktop 4.90.0 и WSL 2.7.13 установлены. Linux Engine не поднялся из-за `sailor-ingest.sock`; автоматическая проверка отклонила команду принудительной остановки процессов и удаления сокета. Ожидается завершение фоновых процессов пользователем. `prepare:examples` действительно запускался и завершился ошибкой недоступного Engine; живой `test:docker` ещё не пройден. Нельзя считать Node/Python реально запущенными, а VM или Kubernetes реализованными.

После восстановления Docker: `npm run prepare:examples`, `npm run test:docker` (Node → Python → Node rollback). Затем стабильный маршрут/очистка предыдущих кандидатов, distributed fencing/agent registry, LXD provisioning и Kubernetes по основному плану. Подробные текущие ограничения — [DOCKER.md](../../apps/hosting/DOCKER.md).
