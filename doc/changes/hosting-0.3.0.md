# Хостинг 0.3.0 — машины LXD

Пока Docker Desktop блокирует реальные контейнерные проверки, реализован независимый срез LXD: типизированные команды создания/питания, отдельные проекции человека и агента, LXD-исполнитель и панель на react2. Состояние питания намеренно не подтверждает подготовку ОС или приложения.

Сервис использует common2 для ролей, RPC, реактивных проекций, receipts и миграции архива. Адаптер занимается только нативным LXD API: immutable fingerprint, CPU/RAM/disk, фиксированный cloud-init с публичным SSH-ключом, принадлежность ресурса, ожидание async-операций и наблюдение конечного состояния. Никаких изменений npm-библиотек или дополнительных схем в примере нет.

Проверены typecheck, build и все четыре suites. Новый тест использует настоящий common2 host, архив v1 с переносом в v2 и сетевых клиентов, но LXD заменён HTTP fixture. Покрыты повтор после потерянного ответа, отказ async-операции, роли и чужие проекты, запрет чужого агента, ревизии, receipts, запуск/остановка и перезапуск исполнителя. Реальные VM, Kubernetes, cloud-init и SSH ещё не проверены.

Запуск и ограничения: [LXD.md](../../apps/hosting/LXD.md). Далее нужны Linux-хост, реальные две машины, подготовка ОС/runtime, снимки/восстановление, связь с версиями приложений, Kubernetes и распределённый fencing. Docker-блокер остаётся отдельным незавершённым пунктом.
