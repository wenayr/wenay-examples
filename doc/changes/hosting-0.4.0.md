# Хостинг 0.4.0: постоянный адрес и очистка кандидатов

Окружение Docker получает постоянный loopback HTTP-адрес. При деплое и rollback меняется только контейнер за этим адресом. Маршрут назначается агентом через команду common2, сохраняется в архиве и повторно привязывается к тому же порту после перезапуска. Если порт занят, агент не выбирает новый молча и не начинает новый деплой этого окружения.

`activeOperation` различает разные развёртывания одного релиза. Шлюз обслуживает подтверждённую активную операцию, после проверки принадлежности контейнера и его адреса. Старые успешные/неудачные кандидаты удаляются после переключения и завершения уже принятых HTTP-запросов; активная и незавершённая операции исключаются. Сервис отмечает `cleaned` в истории только после удаления. При потере ответа удаление повторяется по тому же имени и меткам. Релизы остаются неизменяемыми, rollback создаёт новый контейнер из сохранённого digest.

При проверке обнаружено, что удерживать `store.state` через внешние await небезопасно: живая проекция успевает измениться. Агент использует публичный `store.snapshot()` для прохода и повторно сверяет текущую активную операцию перед удалением. Новый интеграционный тест проверяет, что предыдущий контейнер действительно исчез, а текущий остался.

Проверки: typecheck, build, пять обычных suites, настоящий Docker Node → failed readiness → Python → rollback Node через один адрес. Отдельно проверены завершение медленного запроса на старой версии, передача тела/path/query, hop-by-hop headers, чужой агент, невозможность отчёта об очистке активной операции, неизменность адреса, занятый порт и перезапуск управляющего архива/агента без повторного создания контейнера.

Применены только опубликованные common2/react2; дополнительных сервисов и npm-зависимостей нет. common2 обеспечивает команды, роли, проекции, архив и receipts. HTTP-шлюз и проверка владения контейнером остаются предметными ресурсами хостинга.

Границы: один локальный агент, HTTP/1.1 без WebSocket/CONNECT/TLS, запрос ограничен 30 секундами; отдельный порт на окружение, максимум 64 одновременных соединения на listener. Во время остановки агента маршрут недоступен. Приложение доступно локальным пользователям без авторизации панели. Разные порты дают разные web origins, но не изолируют cookies по имени хоста; это не площадка для недоверенных арендаторов. Для публичного хостинга нужны отдельные домены, TLS и полноценный ingress. Старые окружения без `activeOperation` начинают использовать шлюз после первого успешного деплоя новой версией агента.

HTTP forwarding сверялся с [RFC 9110, Connection](https://www.rfc-editor.org/rfc/rfc9110.html#section-7.6.1). [Запуск и ограничения](../../apps/hosting/DOCKER.md).
