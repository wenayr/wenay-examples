# Настоящий Docker: Node, Python, отказ readiness и откат

9 сентября 2026 пользователь восстановил Docker Desktop. На Linux Engine 29.7.2 выполнен реальный сценарий common2 → агент → контейнеры: Node, неудачная readiness следующей версии с сохранением прежнего рабочего HTTP-адреса, Python, откат к Node. Агент перезапускался между версиями. Ответы приложений подтвердили фактический runtime; все тестовые контейнеры удалены.

При первом реальном запуске исправлена подготовка образов: дочерний CLI получает путь к credential helper, а digest берётся из локального containerd image store. От отдельного registry удалось отказаться. Это уменьшает количество запускаемых процессов и устраняет зависимость подготовки от его локальной сети. Подготовка явно требует доступного manifest digest и не заменяет его config ID.

Учтён бюджет пользователя: максимум 3 ГиБ RAM, последовательные сборки, кандидаты по 64 МиБ/0.25 CPU. Тест дополнен короткой проверкой отказа readiness; производственный deadline агента остался 30 секунд. В последнем замере WSL + Docker backend занимали 2559 МиБ. Непрерывный пик не измерялся; настройки всей WSL не менялись.

common2 обеспечил RPC, ролевые команды, живое состояние и receipts; отдельного транспорта для агента не потребовалось. Предметными остались OCI-адаптер, readiness, профиль ресурсов и решение о переключении активной версии. Реальный тест подтвердил применимость одного контракта к Node и Python, но не подтверждает распределённый fencing, HA, VM или Kubernetes.

Следующий небольшой срез: стабильный адрес приложения и очистка старых успешных кандидатов. В текущем примере адрес меняется между версиями, а старые контейнеры сохраняются до явного удаления. [Запуск и ограничения](../../apps/hosting/DOCKER.md).
