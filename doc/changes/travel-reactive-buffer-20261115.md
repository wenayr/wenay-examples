# Travel: общий буфер и реактивные обновления

Карта и матрица сохраняют прежний интерфейс, но получение цен разделено на адаптер поставщика, общий буфер наблюдений и подписки востребованных HTTP-ресурсов.

- Hosted Worker использует R2 JSON с CAS-допуском, fencing sequence, общим provider cooldown и последним достоверным ответом. SQL для промежуточных цен не добавлен.
- Источник объединяет одинаковую работу; ошибка R2 закрывает новые upstream admissions вместо скрытого memory fallback. Generated hosted entry требует binding BUCKET.
- Storage создаётся лениво; кэшируется готовый адаптер. Весь hosted read принадлежит waitUntil с первого hash/lookup, а его deadline освобождает внутренние R2 queue slots при отмене владельца.
- Профили demand/request-only/economy управляют реальными интервалами. Ручная проверка соблюдает общий допуск, паузу ошибок и hosted gap 15 с, сохраняя исходный checkedAt.
- Клиентские ресурсы используют опубликованные Wenay listenStore/createReconciler; один EventSource вкладки обслуживает активные ресурсы, при недоступности потока действует общий HTTP fallback. Серверная политика приходит также через обычные HTTP-заголовки.
- Фоновая загрузка того же контекста сохраняет demand карточек, мини-матрицы и графиков; новые параметры и закрытие страницы действительно отписывают старые ресурсы.
- Серверный hub объединяет подписчиков одного ресурса, останавливает расписание при последней отписке, восстанавливает retained tail либо делает epoch reset. Частичные и неизвестные ячейки не превращаются в подтверждённо пустые.
- Добавлены строгие границы body/read/cache/pending work; реальные identity headers не попадают в публичные frames или health.

Гарантии и эксплуатационные ограничения описаны в [архитектуре буфера](../../apps/travel/docs/REACTIVE-BUFFER.md). В частности, R2 не является pub/sub, 15 минут удержания не означают физическое удаление объектов, а память и caps относятся к isolate. Production gateway SSE и реальное R2-хранилище проверяются отдельно при публикации.

Один ограниченный запрос реального адаптера TEZ 15.11.2026 дал HTTP 200 и live-наблюдение для Хургады 1–2 декабря / 7 ночей; валидных тарифов в этом ответе не было. Это не подтверждает наличие цены или бронирования. Автоматические проверки используют отдельные управляемые ответы и не изображают их ценами поставщика.

Проверки реализации: весь Travel — 236/236 тестов, typecheck без ошибок, стиль 34 новых/изменённых файлов кода без нарушений. Независимый review закрыл гонки initial GET с resource/reset, request-only без SSE, общий допуск/ошибки, lifecycle подписок, ограничения памяти и ожидающей работы. Дополнительно проверены смена контекста, отмена старых ресурсов, отсутствие async storage-init на статике, владение начальным lookup и освобождение aborted R2 queue. Фактический цикл фоновая загрузка → повторное подключение проверен в managed UI; Node не моделирует Worker context lifetime, который проверяется отдельно в native runtime.
