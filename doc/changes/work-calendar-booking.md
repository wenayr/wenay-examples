# Графическое расписание Booking

26 сентября 2026, ветка `codex/work-calendar`.
Продолжение [графика органайзера](work-calendar-organizer.md).

Первый вид — день с ресурсами и фактическими интервалами встреч. Есть неделя,
фильтр ресурса, выбор часового пояса и масштаб. Начальная прокрутка показывает
встречи или начало рабочего времени. Выбор записи открывает её сохранённые
условия и доступное время, перенос готовит предпросмотр, подтверждение отправляет
одну атомарную команду. Новая запись через прежний выбор услуги и свободного
слота сохранена в раскрываемом блоке.

Временная шкала использует Temporal и реальную длину дня в IANA-зоне: 23/25 часов,
повторяющиеся часы с отдельными UTC-смещениями. Браузерный часовой пояс не меняет
время брони. Клиент видит только свои записи; пустая ячейка его графика не означает
свободную вместимость. Доступные интервалы читает сервер.

## Атомарный перенос

`bookingReschedule(requestId,{orgId,id,revision,key,serviceId,start})` переносит
будущую подтверждённую бронь на совместимую услугу/ресурс той же организации.
Длительность новой услуги должна совпадать с сохранённой длительностью встречи,
депозит — с сохранённым `depositUnits`. Оплата, клиент, число участников и заметка
сохраняются. Применяются целевое расписание, вместимость, буферы и часовой пояс;
уведомления пересчитываются вместе с записью. Неудачная операция ничего не меняет.

Старый `bookingMove` сохраняет прежний контракт. Графический интерфейс использует
новую команду с явным сохранением условий. `calendar.control.read` принимает
optional `bookingId`: только после текущей ACL-проверки исключает эту бронь
из занятой вместимости. Клиентский интерфейс предлагает прежнюю услугу,
сотрудник/владелец — совместимые услуги других ресурсов.

Публичный `useDraggableApi` управляет жестом. Клавиатура: пробел, ↑↓ для времени,
←→ для видимого совместимого ресурса у сотрудника, Enter для предпросмотра,
Escape для отмены. Форма доступна без перетаскивания. Ревизия, организация,
каталог, доступ, соединение и масштаб входят в область действительности жеста.

## Проверено

- Полный Booking `npm test`: домен, помощник, сеть из двух узлов, backup/restore.
- Дополненный `reschedule-check`: конфликт цели, атомарность, длительность/депозит,
  target buffers/zone, права клиента и сотрудника, stale revision, requestId/key,
  восстановленный intent, legacy move, DST gap/fold, отказ held/cancelled.
- Typecheck и production build прошли.
- Браузер: Escape, клавиатурное время, клавиатурный ресурс и время,
  форма назначения ресурса, перенос мышью между ресурсами и подтверждение.
- Сохранённый сценарий: выбрать свободное время, удержать его для клиента,
  подтвердить запись; график получает новую встречу.
- Клиентский браузер показывает три своих встречи и не показывает другого клиента.
- Мобильная ширина 390 px: панель встречи открывается перед графиком.
- Повторный review: после отказа переноса доступность перечитывается. Реальный browser race:
  клиент выбрал 13:00; другой аккаунт занял обе ёмкости скрытыми от клиента удержаниями;
  сервер отказал, встреча осталась в 10:00, предпросмотр снят, слот 13:00 исчез, новый выбор доступен.

Браузерный стенд: `node scripts/browser-session.mjs booking --seed` после сборки.
Два ресурса, совместимые услуги, пересечение в пределах вместимости и удержание
с другими условиями создаются публичными командами в собственном временном архиве.
Вызовы платного ИИ, платежи и настоящие письма не выполнялись.

Физический touch и браузерная проверка перехода DST не выполнены; DST подтверждён
доменными и Temporal-проверками. Общий `check:all` ветки прошёл: 35 проверок приложений,
36 шагов с отсутствующим catalog build; scaffold, sync, style, links и STATUS прошли.
Повтор typecheck/build органайзера после финального UI review и последующий check:repo также прошли.
