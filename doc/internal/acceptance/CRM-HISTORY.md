# Orbit — приёмка и история

Перенесено 11 сентября 2026 из `apps/crm/README.md` (задача R04 [плана 3](../../PLAN3-TASKS.md)). Это результат приёмки на указанные даты, а не действующая инструкция. Текущее состояние проверок — [STATUS](../../STATUS.md).

## Размещение через пример хостинга

Dockerfile закрепляет Node 24 Alpine по digest, запускает приложение от пользователя node и хранит данные в `/data`. Перед сборкой выполните `npm run build`. Собственные исходники organizer включены в образ; тесты, node_modules с рабочей машины, секреты и пользовательские данные исключены. `APP_RELEASE` виден в `/health`. Для сохранения данных нужен отдельный volume и стабильные service credentials.

```text
npm run build
docker build --memory 768m --build-arg APP_RELEASE=first -t wenay-examples.local/crm:first .
docker build --memory 768m --build-arg APP_RELEASE=second -t wenay-examples.local/crm:second .
```

Из `apps/hosting` исходного репозитория: `node --import tsx backend/crm-live-check.ts`. 10 сентября 2026 реальная приёмка first → second → rollback через hosting authority/agent прошла. Адрес gateway остался прежним, старые клиенты и ресурсы переподключились. Сохранены внутреннее взаимодействие, опубликованное предложение, согласование клиента, одна производная задача, CSV import checkpoint и добавленный контакт. Клиент не увидел внутреннюю заметку; повтор согласования не создал вторую задачу.

Контейнер ограничен 256 МиБ; контрольные снимки памяти 57.08/57.07/57.08 МиБ. Сборки с лимитом 768 МиБ выполнялись последовательно. Собственные контейнеры, volume и временный архив удалены тестом; образы оставлены. Это проверка совместимых версий с одной схемой данных, без произвольной миграции или нескольких writer. Межпроектный hosting-тест не переносится scaffold-копировщиком.
