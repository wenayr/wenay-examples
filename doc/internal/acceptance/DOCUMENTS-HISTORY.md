# Papertrail — приёмка и история

Перенесено 11 сентября 2026 из `apps/documents/README.md` (задача R04 [плана 3](../../PLAN3-TASKS.md)). Это результаты приёмки на указанные даты и разбор принятых решений, а не действующая инструкция. Текущее состояние проверок — [STATUS](../../STATUS.md).

## Приёмка размещения и повторные прогоны

10.09.2026 `apps/hosting/backend/documents-live-check.ts` прошёл настоящий маршрут `first → second → rollback first` через постоянный gateway. В контейнере выполнены Node CSV, Python CSV отдельным процессом и текстовый PDF через pdfjs. Проверяющий изменил CSV и утвердил результаты; после каждого размещения сохранены JSON-экспорт, утверждение и точные исходные байты всех трёх файлов. Сессии остаются теми же, ресурс открывается в свежем поколении SC1. Произвольная несовместимая миграция этим не проверяется.

Из `apps/hosting`: `npm run test:documents`. Предварительно собрать образы `wenay-examples.local/documents:first` и `:second` с соответствующим `APP_RELEASE`; Dockerfile включает Python. Образы собирались последовательно с пределом сборки 768 МиБ. Тест создаёт один свой контейнер с жёстким пределом 256 МиБ и удаляет только свои ресурсы.

Выборочные `docker stats` после операций: Node CSV 56.12 МиБ, Python CSV 56.25 МиБ, PDF 55.89 МиБ, после обновления/отката около 55.57 МиБ. Это текущие замеры после операций, **не пиковая память** обработчиков или всей системы. Контейнер не завершался по OOM. Проверка не заявляет нагрузочный benchmark или перенос состояния между независимыми машинами.

### Повторная приёмка после выделения CSV-парсера

10.09.2026 повторно прошли полный `npm test` с настоящим Python из локального runtime, проверка типов и production-сборка после изменения общего replay-hook и выделения `csv-table.ts` для второго потребителя CRM. Заново собранные Docker-образы прошли `first → second → rollback first` с Node/Python CSV, текстовым PDF, утверждёнными экспортами, исходными байтами и сохранённой сессией через gateway.

При повторной проверке наблюдаемая память после Node CSV — 58.39 МиБ, Python CSV — 59.68 МиБ, PDF — 60.23 МиБ; предел контейнера 256 МиБ. Эти выборки не измеряют пик.

## Что дало использование библиотек

- `schemaCommand` и service definition: входы, ролевые фасады, серверный контроль, receipts команд, наблюдаемое состояние и репликация.
- `createAiRunHost` с `AiRunPersistencePort`: долговечный жизненный цикл задания, идентификаторы запусков, прогресс, отмена и восстановление неопределённой работы. Здесь исполнитель извлекает данные; он не является моделью ИИ.
- `createLocalBlobStorage`: ограниченные загрузки, сохранение байтов и контроль доступа. Байты файлов не передаются с каждой подпиской.
- `createAsyncQueue(1)`: последовательные изменения файлов/метаданных и очистка, исключающие гонку удаления с новой загрузкой.
- `createProcessResource`: запуск и закрытие Python/PDF-процесса, ограниченный вывод, тайм-аут и отмена.
- `wenay-react2`: подключение сервиса, команды, подписки, работа с ресурсами и интерфейс состояния операций.

Роли внутри организации, правила проверки, лимиты таблицы, утверждение и экспорт относятся к приложению. Обработчик заменяется через `DocumentProcessor.extract`; схема интерфейса и оркестрация задания при этом сохраняются.

## Почему обработка на createAiRunHost

Длительная обработка построена на `createAiRunHost`, а не на специализированном `createFileJobHost`: решающим оказалось восстановление после перезапуска. Прерванный запуск разбирается явно через `recovery` — дошедший до проверки документ засчитывается, остальные получают разрешение на новую попытку. В контракте файлового хоста такой поверхности нет, и её пришлось бы написать самим.

Разбор с условиями пересмотра: [сравнение с createFileJobHost](../../reports/file-job-host-comparison.md).
