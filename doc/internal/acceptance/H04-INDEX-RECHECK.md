# H04 — повторная браузерная приёмка базы знаний

Дата: 11 сентября 2026. Задача E01 [плана 3](../../PLAN3-TASKS.md). Строка [H04](../../SAAS-EXAMPLES-BACKLOG.md) требовала повторить браузерную проверку после добавления фонового индекса статей.

## Как проверяли

Сервис поддержки запущен обычным способом (`npm start`, порт 3810, каталог `support-data` с демоданными), интерфейс открыт в браузере, вход владельцем через кнопку демо-аккаунта.

1. Раздел «База знаний» → «+ Новая статья».
2. Заголовок «Проверка индекса после добавления», текст с заведомо уникальным словом **криптофлокс**.
3. «Сохранить черновик» — статья появилась в списке с меткой «Черновик», в редакторе показано состояние «Черновик».
4. «Опубликовать» — метка сменилась на «Опубликовано», появились «Снять с публикации» и «История · 1 версий».
5. В поле «Поиск в базе знаний» введено слово `криптофлокс`.

## Результат

Поиск сразу вернул **ровно одну** карточку — только что опубликованную статью; три демонстрационные статьи («Как пригласить коллегу», «Экспорт данных», «Внутренняя инструкция») из выдачи исчезли. То есть только что опубликованная версия индексируется при первом же запросе, без отдельного прогрева и без перезапуска сервиса.

## Границы этой проверки

- Проверялась работа поиска по опубликованной статье, а не качество ранжирования: поиск локальный и по ключевым словам, без модели и embeddings.
- Индекс восстанавливается из основного архива; отдельного долговечного писателя у него нет — это проверяется тестом `backend/article-index-check.ts`, а не браузером.
- Проверка велась одним владельцем в одной организации. Видимость статьи клиентом и отсечение снятой с публикации статьи проверяются тем же автоматическим тестом.
