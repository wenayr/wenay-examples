# Signal — приёмка и история

Перенесено 11 сентября 2026 из `apps/monitoring/README.md` (задача R04 [плана 3](../../PLAN3-TASKS.md)). Это результат приёмки на указанные даты, а не действующая инструкция. Текущее состояние проверок — [STATUS](../../STATUS.md).

## Самостоятельная упаковка

Из корня: `node scripts/create-saas-example.mjs monitoring <новый-пустой-каталог> --name my-monitoring`. Переносятся разрешённые исходники, точные зависимости, Dockerfile и правила. Рабочие `monitoring-data`, `preview`, `.env`, секреты и сборка не копируются. Сервисный ID `monitoring`, маршруты и порт 3816 сохраняются.

Dockerfile использует закреплённый Node 24 Alpine и пользователя `node`, данные — `/data`. Предложены собственный `/health` и явно обозначенная отсутствующая локальная страница для лёгкой приёмки инцидента. Проверки не выполняются до создания монитора. Переопределите `MONITOR_TARGETS_JSON` для своей установки. Dockerfile ожидает предварительный `npm run build`.

Живая проверка `npm run test:monitoring` из `apps/hosting` прошла: настоящий HTTP 404 открывает инцидент/задачу, обновление сохраняет их и частную сводку, HTTP 200 закрывает инцидент, откат сохраняет историю, checklist, свежую сводку и отзыв дежурного. Старый bearer явно отклоняется; публичный статус не содержит частных заметок. Используются только локальные цели самого контейнера.
