# P01 — журнал webhook и ручной повтор в браузере

Дата: 11 сентября 2026. Задача E01 [плана 3](../../PLAN3-TASKS.md). Строки [P01 и P07](../../SAAS-EXAMPLES-BACKLOG.md) оставались частичными: заполненный журнал доставки с ручным повтором проверялся только через backend.

## Как проверяли

Учёт запущен с разрешённым получателем: `METERING_WEBHOOK_ORIGINS=http://127.0.0.1:3902`, порт 3812, пустой каталог данных. Вход владельцем через кнопку демо-аккаунта.

1. «Интеграции» → «Новый получатель», адрес `http://127.0.0.1:3902/hook` → «Добавить получателя». Секрет подписи показан один раз.
2. По этому адресу **ничего не слушало**, поэтому доставка должна была провалиться.
3. «Ключи доступа» → создан ключ «Приёмка P01» с правами `usage:read` и `usage:write`; секрет показан один раз.
4. «API-клиент» → подключение этим ключом → операция «Учесть расход» с основанием «Приёмка P01: журнал доставки». Сервис ответил `status: committed`.
5. «Интеграции»: в журнале появилась доставка `usage.committed`, состояние «Ожидает», затем «Не доставлено», 5 попыток.
6. Запущен простой получатель на 3902 (обычный Node-сервер, отвечает 200).
7. В карточке доставки — «Повторить доставку».

## Результат

Журнал показывает каждую попытку отдельной строкой: «Попытка 1…5, 11 сент., 20:08, Нет HTTP-ответа, Доставка не подтверждена: сеть, время ожидания или запрещённый адрес». После ручного повтора появилась «Попытка 6 — HTTP 200», состояние доставки сменилось на **«Доставлено»**.

Получатель записал в свой журнал:

```text
получено POST /hook подпись sha256=7b21229d61fa0 событие c00a132d75665c2c3fafb75576126ed07ff67c2a1c0fd27b109d39bd861ed723
```

То есть повтор отправил **то же самое событие** с тем же идентификатором и подписью исходных байтов — получатель обязан дедуплицировать по нему, как и написано в интерфейсе.

## Границы этой проверки

- Получатель — локальный тестовый сервер, отвечающий 200 на что угодно; проверку подписи на его стороне здесь не выполняли (её проверяет `backend/webhook-check.ts`).
- Автоматические попытки шли по сохранённым срокам (1/2/4/8 секунд); точность интервалов не измерялась.
- Проверялся один владелец и одна организация; изоляция журнала между организациями проверяется доменным тестом.
- Карточка доставки — свёрнутый `<details>`: кнопка повтора появляется только после раскрытия записи.
