### Исторический порядок выполнения пакета 0.8.0

Работать в исходных репозиториях библиотек. Использовать существующие публичные примитивы, сначала определить экспортируемые границы и тесты. Не добавлять Zod, параллельный транспорт, replay, reconnect или другую систему типов. Не помещать в библиотеку пиццерию целиком.

C2 и C3 согласовать по одному контракту definition/descriptor до реализации; C4 строить поверх C3. C1 можно исправлять в текущем поставляемом scaffold независимо, затем сохранить исправление при выделении runtime. R1 и R3 меняют одну механику reorder: выполнять последовательно или согласовать общий activator/scroll-контракт. C5/C6 не должны задерживать первые шесть задач. R2 независим.

После изменений выпустить точные npm-версии. Только затем перевести пример на публичные экспорты, удалить заменённые локальные файлы и повторить `npm run typecheck`, `npm test`, `npm run build`, `npm run build:organizer`. Не подменять установленный пакет локальной сборкой. Для каждой задачи отдельные критерии приведены в связанном документе.

Результат отдавать с перечнем экспортов, версией, проверками и перечнем реально удаляемых адаптеров. Не закрывать C2/C3 только переименованием папок или очередной генерацией тех же файлов в каждом приложении.

## Что исправлять в примере, а не требовать от библиотек

- `frontend/locations.tsx`: адаптация завершена в [0.10.0](../changes/0.10.0.md). `NetworkOwner` использует общий action hook, строки `OwnerOverview` владеют сессиями через существующие hooks; новое API не потребовалось.
- `ServiceView` проверяет обязательные верхние ключи после очистки закрытой проекции. `ready` означает первую готовность; текущие права и соединение уже доступны отдельно. Удобный объединённый компонент допустим позже, но доказанного недостатка базового hook здесь нет.
- Описание пакетов в `organizer/README.md` приведено к текущим версиям при миграции 0.9.0.
- Выбор ролей, FormData → предметное объединение, рецепты, склад, сроки, чек-листы, фото по умолчанию, загрузка повара, архивация задач и обмен между отдельно развёрнутыми продуктами остаются приложению. Универсальный form-builder, календарь и HA-writer не обоснованы этим аудитом.
