# R4: клавиатурное перемещение для useDraggableApi

**Закрыто: опубликованная 3.4.0 установлена в обоих приложениях; Note переведён на публичный API. [Результаты приёмки](../changes/react2-3.4.0.md).** Ниже исходная постановка для истории.

Предложение по результатам S2, 10 сентября 2026. Проверены опубликованные common2 2.19.0 / react2 3.3.0. Это улучшение общей композиции, не ошибка существующего mouse/touch API и не блокер готового примера.

## Конкретный потребитель

В `apps/pizzeria/organizer/canvas.tsx`, компонент `Note`, свободная заметка двигается через публичный `useDraggableApi({holdMs:0, trackState:false, onMove, onDragStart, onDragEnd})`. `getPosition`, `setPosition`, `resetPosition`, `cancelDrag` уже доступны. Для клавиатуры пришлось отдельно хранить состояние захвата, обрабатывать Space/Enter/Escape/стрелки/Shift и сводить начало, предпросмотр, commit и cancel с pointer-жизненным циклом. Похожие действия уже решены внутри `useReorderBoard`, но его модель — колонки и индексы; свободная поверхность имеет координаты.

Проверка в примере: два сотрудника открывают «Свободную доску», первый берёт заметку Пробелом, двигает стрелками (Shift увеличивает шаг), второй видит transient preview. Enter отправляет одну команду; Escape отменяет. При изменении заметки другим участником или потере разрешения приложение вызывает cancel. Сохранённое положение и ревизия определяются сервером.

## Минимальная общая работа

Проверить, можно ли поверх текущего drag-примитива предоставить небольшой поддерживаемый keyboard-адаптер либо opt-in возможность в `useDraggableApi`. Названия/форма нового API здесь не задаются. Нужны единое состояние pointer/keyboard, согласованные start/move/end/cancel, фокусируемая ручка и настраиваемый шаг. Одновременно два способа ввода не должны владеть одним жестом.

В библиотеку **не переносить** RPC, комнату, TTL, доступ к заметкам, авторство, конфликт ревизии, координатную систему конкретной доски, размер канвы или вычисление сохранённой команды. Ограничение позиции остаётся политикой потребителя. Не делать новый transport или универсальный графический редактор.

## Приёмка

1. Space/Enter начинает жест с ручки, стрелки дают move, Enter завершает ровно один раз, Escape отменяет без commit. Шаг и модификатор можно настроить.
2. Программный cancel и unmount одинаково завершают pointer/keyboard; поздний mouseup не вызывает commit после cancel.
3. Состояние isDragging/input mode и текущая позиция согласованы; trackState:false не требует React-рендера для каждого move. setPosition/resetPosition сохраняют документированную семантику.
4. Ввод в textarea/select, кнопка удаления и обычная прокрутка не перехватываются. Фокус не перескакивает к чужому объекту. Два экземпляра независимы.
5. Pointer/touch и существующие useReorder/useReorderBoard не регрессируют. После публикации удалить из `Note` только повторённую клавиатурную механику, сохранив предметные проверки и команды.

Если текущего публичного API достаточно для такого адаптера без второго состояния жеста, достаточно рабочего типизированного примера; обязательное расширение API не требуется.
