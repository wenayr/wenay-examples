# R1 — перестановка клавиатурой и отдельная доступная ручка

react2 3.2.0, common2 2.17.0; органайзер 0.8.0. Приоритет высокий среди улучшений UI: мышь работает, полного клавиатурного эквивалента перестановки нет.

**Факт.** `organizer/board.tsx` использует `<span role="img" {...item.props}>` для ручки. `ReorderItem.props` в опубликованном `useReorder.d.ts` содержит только onMouseDown/onTouchStart. `useReorderBoard.js:139` исключает начало drag с `input, button, select, textarea, a`. Поэтому простая замена span на button прекращает pointer drag. Поле статуса в приложении позволяет менять колонку, но всегда передаёт `beforeId:''`; порядок внутри колонки клавиатурой не задаётся.

**Работа.** Дополнить публичные `useReorder`/`useReorderBoard` явным activator/handle-контрактом: на настоящую кнопку ставятся отдельные props, остальные интерактивные элементы карточки по-прежнему не начинают drag. Реализовать клавиатурное начало/подтверждение Space/Enter, перемещение стрелками по слотам и колонкам, Escape без commit. Выдавать необходимые состояния для доступных описаний; текст объявлений и оформление остаются приложению.

**Воспроизведение.** Открыть доску с двумя ручными задачами в одной колонке; пройти Tab и попробовать поменять их порядок. Затем поставить существующие item.props на button и повторить перенос мышью. Сверить public `.d.ts` и documented mouse/touch-контракт. Не требуется менять серверную команду workMoveTask.

**Приёмка.** Одна и та же операция доступна pointer/touch/keyboard; клавиатурная отмена не вызывает commit; подтверждение вызывает ровно один commit. canDrag запрещает все способы начала. Фокус сохраняется на перемещённой карточке, текстовое поле/кнопка действия внутри неё работают независимо. При удалении карточки, смене ролей и unmount активный перенос безопасно завершается или отменяется. Hook tests и браузерный сценарий органайзера обязательны.
