# Booking backend: фактическая приёмка

10 сентября 2026. Общие механизмы: `wenay-common2 2.21.1`, `wenay-react2 3.5.1`, время `@js-temporal/polyfill 0.5.1`.

## Выполнено

R01–R03: отдельная модель ресурса и услуги, IANA-зона, расписание/исключения, ограниченная доступность, буферы, capacity sweep, удержание TTL и атомарное подтверждение на authority, устойчивые прикладные ключи намерения.

R05: отмена, перенос с проверкой до изменения старой брони, exact-slot waitlist с сохранённым предложением обычного hold. Предложения выбираются по createdAt/id среди подходящих заявок. Приоритета очереди над прямой записью не заявляем; обе операции конкурируют на одной authority-проверке.

Локальная часть R06: настройки напоминаний, сохранённые pending/delivered/cancelled события, отмена устаревшей версии, тестовые единицы депозита и дедупликация eventId. Поздняя «оплата» не подтверждает истёкшую бронь, результат refundDue. Реальные сообщения, платёжный провайдер и его webhook отсутствуют. `depositSimulate` нельзя использовать как подтверждение настоящей оплаты.

## Проверено

- `npm run typecheck` и `npm run build` прошли на окончательном backend + frontend, включая помощника. Сборка предупреждает о chunk >500KB и текущем способе загрузки Vite config; это не ошибка типов или сборки.
- Полный `npm test` прошёл: доменный сценарий через настоящий service leader, проверки помощника и сетевой сценарий с authority + двумя serving nodes.
- Домен: Europe/Berlin spring gap и autumn fold (два разных UTC для 02:30), Australia/Lord_Howe 30-минутный переход, исключения/закрытая дата, неверные окна/зона, диапазон, пересекающиеся и смежные интервалы, буферы, гонка последнего места, TTL, клиентская приватность, роли/чужая организация, semantic conflict, сохранение старой брони при ошибке переноса, одно предложение ожидания, напоминания и повтор/поздний тестовый депозит.
- Сеть: два клиента соревнуются за одно место; serving node действительно выбран; его отключение переводит прежний workspace store на другой узел; отмена создаёт одно предложение; оно истекает настоящим таймером reconciler без новой пользовательской команды; authority после перезапуска восстанавливает подтверждённую бронь и прикладной key.
- Временные процессы и архив сетевого теста закрыты и удалены только в собственном mkdtemp-каталоге. Внешние AI/платёжные/уведомительные сервисы не запускались.

## R07: помощник

`createAiRunHost` управляет явным testparser без языковой модели. Только каталог доступных услуг, версии и IANA-зоны передаются исполнителю. Отдельное чтение частного результата повторяет текущий ACL/catalog guard и availability. Helper не создаёт hold. `assistant-check.ts` прошёл: отсутствие записи, изменение вместимости после предложения, чужая услуга/организация, отмена, тайм-аут, поздний результат, отзыв роли, очищенные ошибки и сохранение частного результата после рестарта.

Владелец frontend отдельно прошёл браузером применение предложения → ручной hold → confirm, основные роли и мобильный экран 375px. Подробная проверка с границами: `doc/reports/BOOKING-UI-ACCEPTANCE.md`. Preview 3814 принадлежит той задаче, не Docker-приёмке.

## R08: упаковка и размещение

`scripts/create-saas-example.mjs booking work/scaffold-booking --name scaffold-booking` создал 39 разрешённых файлов без соседних runtime, userdata, секретов и node_modules. Чистые `npm ci`, `npm run typecheck`, `npm run build` и полный `npm test` прошли. Общий scaffold-check прошёл на support/documents/metering/crm/booking. README/рецепт аренды и manifest: `doc/SAAS-RECIPES.md`.

`apps/hosting/backend/booking-live-check.ts` прошёл на реальном hosting authority и Docker agent: deploy first → second → rollback first. После смены образа удержание сохранилось, затем подтвердилось; rollback сохранил подтверждённую бронь и напоминание. Семантический повтор не продублировал запись, чужая бронь не заняла последнее место. Прежний клиент и calendar resource переподключились по неизменному gateway URL. В конце подтверждённая бронь отменена обычной командой.

Образ Node 24 Alpine закреплён по digest, `USER node`, один writer и стабильный `/data` volume. Runtime cap 256MiB, снимки памяти 59.45/60.17/59.12MiB; последовательные сборки с параметром memory768m. Собственные контейнеры, volume и временный каталог удалены. Образы остаются локально:

- first `wenay-examples.local/booking@sha256:12c19075c22cdd9f5a4e8c9ddbeb193886e32467a196e732eaf8ec709968b610`
- second `wenay-examples.local/booking@sha256:4cf642dc7a1bec00369994e2c482edb0148975f0a3973b79954d8759b76cba27`

Это совместимые образы одной схемы. Произвольные миграции, несколько независимых писателей и восстановление потерянного диска не проверены. Межпроектная Docker-приёмка не входит в standalone npm test.

## Границы

UI/R04 проверен отдельным исполнителем с указанным отчётом. Пример обслуживает реальные чтения на serving nodes при одном авторитетном писателе вместимости. Расписание не хранит UTC вместо часового пояса, а подтверждённые обещания сохраняет как UTC-интервалы. Полный контракт и правила DST: `apps/booking/README.md`.

Нового дефекта библиотек на этом этапе не найдено: role facade, schemaCommand, Store, resources, receipts, reconnect и createReconciler покрыли инфраструктуру. Расписание, вместимость, ожидание и депозитные статусы остаются предметными правилами приложения.
