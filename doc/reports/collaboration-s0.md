# S0: проверка основы совместной доски

9 сентября 2026 года. npm latest сверены и совпадают с установленными версиями: common2 2.18.1/react2 3.3.0. Зависимости и приложение 0.10.0 не обновлялись; добавлены диагностические сценарии и задания.

## Что проверено

Публичный peer API передаёт независимые курсоры двух серверных session ID и даёт актуальный снимок позднему читателю при коротком журнале. Разные `createPeerHost` изолируют комнаты. Presence по одинаковому account считается по числу подключений; это не два независимых курсора, поэтому соответствие вкладка → серверная сессия задаётся композицией.

Дополнительно выполнен настоящий сетевой сценарий: Socket.IO + common2 RPC, проверка токенов публичным service leader, два клиента одного аккаунта и наблюдатель. Оба курсора приходят независимо; штатное отключение socket удаляет presence, другая вкладка продолжает существовать. Это лёгкий локальный стенд, не тест нескольких хостов и не браузерная приёмка.

## Запуск и интерпретация

Из `apps/pizzeria`:

```sh
npm run typecheck
npm run test:peer-contract
npm run repro:peer-close
npm run repro:peer-network
npm run repro:peer-network -- --shutdown-only
```

Typecheck и положительные peer-контракты проходят. Команды `repro:*` по умолчанию подтверждают известное неправильное поведение и печатают `REPRODUCED`; их нулевой exit code **не означает**, что дефект исправлен. При неизвестном результате они падают. После публикации исправлений использовать `--expect-fixed`: этот режим требует безопасного закрытия и отсутствия необработанных ошибок.

Режимы `repro:peer-close --expect-fixed` и `repro:peer-network --shutdown-only --expect-fixed` также запущены на 2.18.1: оба ожидаемо падают на соответствующих утверждениях PC1/PC2. Для передачи подготовлены воспроизводимые красные regression-проверки.

Диагностический обработчик `unhandledRejection` существует только внутри сетевого воспроизведения; приложение не получает глобальное подавление ошибок. Сетевой host и клиенты после проверки освобождаются. Новые Docker-контейнеры, VM, тяжёлые сборки и модели не запускались; текущие preview не изменялись.

## Следующее действие

Передать узкий пакет PC1/PC2/SC1 разработчику common2. После опубликованного исправления обновить точную npm-версию и повторить проверки в режиме `--expect-fixed`; затем подключить к самостоятельному органайзеру публичную композицию presence/курсоров и пройти S1 в браузере. SC1 может закрыться документированным адаптером текущих API, если он не дублирует service/session runtime.

S1 **ещё не реализован в интерфейсе**. Рабочую доску с утечкой закрытых фасадов и необработанными ошибками завершения не объявляем готовой. До интеграции остаются проверка отзыва прав, ограничение видимости конкретной карточки, срок актуальности, координаты, следование за участником и браузерные сценарии. Эти предметные задачи не выданы библиотеке.
