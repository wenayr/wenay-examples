# Forms — самостоятельная копия и живая установка

Проверено 10 сентября 2026. Опубликованные зависимости: `wenay-common2@2.21.1`, `wenay-react2@3.5.1`. Платных запросов и внешнего ИИ-провайдера нет. Группировка остаётся явно обозначенным детерминированным демо.

## Самостоятельная копия

`scripts/create-saas-example.mjs forms <пустой каталог> --name forms-standalone` переносит явный набор из 42 файлов: backend, frontend, локальные адаптеры shared, точный lockfile, Dockerfile и общие правила. Исходный сервис сохраняет ID `forms` и порт 3815; меняется npm-имя.

`scripts/scaffold-check.mjs` прошёл для шести шаблонов. Для Forms отдельно проверены архив, задания экспорта/группировки, публичный клиент, сетевые тесты; внедрённые маркеры `.env`, сырых ответов, частных групп, постороннего backend-файла и старой сборки не попадают в копию. Общие проверки запрещают выход локальных импортов за пределы приложения, отсутствующие исходники, непинованные зависимости, перезапись, symlink/junction.

В отдельном временном каталоге, без соседних приложений, последовательно прошли:

- `npm ci --no-audit --no-fund`: 162 пакета.
- `npm run typecheck` и `npm run build`: итоговый frontend `index-DEkdO-nn.js`, CSS `index-CUmWGEDX.css`.
- `npm test`: domain, сетевой SC1 с экспортом и восстановлением, grouping, authority + два serving nodes с переключением, отзывом доступа и полным рестартом.

Последняя серия из 20 локальных ответов в этой копии заняла 28 ms, p50 18 ms, p95 27 ms. Это малый приёмочный поток, не нагрузочная оценка производственного сервиса.

Сборка сообщает о будущем native config loader Vite и общем JS chunk около 590 kB; ошибок установки, типов, сборки и тестов нет.

## Docker и настоящий хостинг

Оба образа собраны **из проверенной самостоятельной копии** с npm-именем `forms-standalone`, неизменным сервисом `forms` и финальным интерфейсом. Базовый Node 24 Alpine закреплён digest. Сборки последовательные, `--memory 768m`, Node heap установки ограничен 256 MiB. Контейнер запускается под пользователем `node`, постоянные данные находятся в `/data`.

| Образ | Digest |
| --- | --- |
| `wenay-examples.local/forms:first` | `sha256:8e2037da6e35fe2cc1821c0070cb45c0570509d83aec3a82297a770023b5adbf` |
| `wenay-examples.local/forms:second` | `sha256:739266674e122e18bf040c1e89d54c9356efecf7f7bc205587efff4e6274be8d` |

`npm run test:forms` в `apps/hosting` прошёл через настоящий сервис хостинга, Docker-agent, стабильный gateway и общий именованный том: `first → second → rollback first`. Релизы различаются меткой `APP_RELEASE`, формат данных совместим. Эта проверка не объявляет испытанной миграцию между несовместимыми схемами.

Сценарий создаёт публикацию и три ответа, запускает группировку и реальный JSON-экспорт, вручную объединяет группы. После обновления и отката проверяет неизменяемую публикацию, три записи без дублей, `answersRevision`, исправленную группу с тремя идентификаторами и прежние bytes выгрузки. Повтор публикации выдаёт `token: null`; повтор ответа не увеличивает число записей. Содержание ответов и названия частных групп отсутствуют в общих подписках/AI replay.

На втором релизе отзываются роль аналитика и публичная ссылка; сохранённые открытые SC1-фасады теряют доступ. После отката **стандартный REST библиотеки** проверяет старые bearer-токены: запись респондента и workspace аналитика явно отклонены как forbidden, без принятия сетевого таймаута за успех. Повторный вход по старой публичной ссылке отклонён. Владелец сохраняет доступ к прежним ответам, группировке и выгрузке.

Каждый контейнер проверен на фактический лимит 256 MiB, 0.5 CPU и собственную метку владельца теста. Измеренные снимки памяти: first 58.46 MiB, second 57.27 MiB, rollback 56.88 MiB. Это снимки, не измерение пикового расхода. Тест удалил только свои контейнеры, том и временные данные; чужие ресурсы не затрагивались.

Повторный запуск использует те же digest и создаёт отдельные случайно именованные ресурсы. Браузерная и мобильная приёмка описываются отдельно; серверная упаковка их не подменяет.
