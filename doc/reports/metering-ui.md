# Counter: интерфейс учёта API

Проверено 10 сентября 2026. Пример: `apps/metering`, preview `http://127.0.0.1:3812/`.

## Реализовано

- Кабинет владельца, аудитора и отдельной организации: период, расход, текущий резерв, остаток тестового лимита, параллельные операции, история действий. Графика построена CSS, без отдельной библиотеки диаграмм.
- Ключи с отдельными `usage:read` / `usage:write`, сроком действия, однократным секретом и отзывом. Секрет передаётся в API-клиент только через память компонента.
- API-клиент входит отдельной сессией ключа. Владелец не выполняет команды расхода от собственного имени. Действия: учёт, резерв, подтверждение, освобождение, неизвестный исход. Пользователь явно управляет ID события и повтором.
- `usage.control.identity/read` проверяют права ключа при запросе. Чтение показывает снимок с временем получения; API-клиент не держит подписку workspace.
- Журнал использует публичный `AgGridTable` из `wenay-react2/grid`: сортировка, фильтры, быстрый поиск, виртуализация. Компонент и AG Grid загружаются при открытии раздела.
- Интеграции: состояние тестовой подписки, получатели webhook, однократный секрет подписи, включение/отключение, история попыток, ручной повтор неудачной доставки. Без разрешённого оператором адреса получателя создать нельзя.
- Все сетевые команды и ресурсные сессии идут через common2, React lifecycle — через `useOwnedClient`, `useClientStore` и прикладные адаптеры над `useServiceCommands`. Схем Zod и дополнительного транспорта нет.

## Фактически пройдено в браузере

На отдельной Chrome-вкладке, с отдельным локальным архивом `apps/metering/metering-data/ui-preview`:

1. Owner вошёл в Northstar Studio и создал ключ с чтением/записью. Однократный секрет передан кнопкой в отдельный API-клиент, без чтения секрета инструментом и без вывода в отчёт.
2. API-клиент подключился; резерв 20 единиц вернул `reserved`, затем подтверждение 12 вернуло `committed`. Повтор подтверждения с тем же ID вернул `fresh:false`.
3. Журнал показал ровно одну операцию, учтено 12, исходный резерв 20. Быстрый поиск скрывает строку по отсутствующему тексту и возвращает её по «Проверка».
4. После отзыва ключ отображается как «Отозван». Проверка уже подключённой сессии после отзыва выполняется отдельным backend-тестом, в этом UI-сеансе клиент ранее был закрыт навигацией.
5. Создание webhook на неразрешённый локальный адрес отклонено с понятной ошибкой. Исходящий запрос не требовался. Доставка, подписи и ретраи проверяются backend-тестами; заполненный список доставок через UI в этой проверке не проходился.
6. Auditor видит расход 12, резерв 0, остаток 988, параметры ключа; кнопок создания/отзыва ключей, изменения лимита и создания webhook нет.
7. Outsider видит Harbor Labs с расходом 0 и лимитом 100; событий и ключей Northstar нет.
8. Снимки desktop и ширины 450 просмотрены. Мобильные страницы ключей и обзора помещаются по ширине; измеренная ширина документа и содержимого равны 435 px (оставшиеся 15 px — полоса прокрутки). Навигация прокручивается внутри своей строки. Временный viewport сброшен.

## Проверки и ограничения

`npm run typecheck` и `npm run build` проходят. Обнаруженный браузером отсутствующий `QuickFilterModule` исправлен передачей модуля непосредственно в AgGridTable: это прикладная настройка optional-функции, а не дефект библиотеки. После исправления поиск проверен; новых ошибок консоли в этом сценарии нет. Основание: [официальная документация Quick Filter](https://www.ag-grid.com/react-data-grid/filter-quick/), комментарий опубликованного публичного механизма модулей react2.

Основной JS около 463 KB (144 KB gzip), отложенный журнал около 979 KB (270 KB gzip). Vite сообщает предупреждение о размере отложенного AG Grid и текущем формате конфигурации; это не ошибки сборки. Лимит в историческом периоде берётся из текущей настройки организации, отдельной истории тарифных лимитов UI не вводит.

Полная протокольная проверка двух serving nodes, expiry, replay, отмены и совместной работы support/documents выполняется backend-командами проекта; результаты этих проверок не подменяются кликами браузера. Реальных денежных платежей и платных запросов ИИ здесь нет.
