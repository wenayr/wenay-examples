# Support: интерфейс и проверка

Дата: 10 сентября 2026. Пример: `apps/support`.

## Реализовано

- Русский интерфейс Northstar: вход с пятью демонстрационными ролями, выбор организации, статус подключения, выход из аккаунта.
- Обращения: поиск по теме и доступным сообщениям, открытые/решённые/мои/все, создание, переписка, приватные заметки сотрудников, назначение, статус, приоритет, срок первого ответа.
- Контекст обращения: опубликованные статьи, вложения, помощник с отдельным действием вставки текста в черновик. Отправка ответа остаётся отдельным действием человека.
- База знаний: поиск, просмотр клиентом, редактор сотрудников, импорт TXT/Markdown до 30 КБ в несохранённый черновик, публикация руководителем, архив, история и восстановление в новый черновик.
- Изменение статьи другим участником сохраняет локальный текст и предлагает загрузить актуальную версию; запись устаревшей версии заблокирована в форме и проверяется сервером.
- Команда: роли, фактическое количество назначенных открытых обращений, создание организации, одноразовые приглашения, принятие кода, отзыв приглашения.
- История действий с русскими названиями и ограничением интерфейса для руководителей.
- Макеты для узких экранов: горизонтальный список обращений, вертикальная переписка и контекст, доступный выход из аккаунта. Оформлены состояния ожидания, ошибки, пустые результаты и потеря связи.
- При смене роли пересоздаётся редактор ответа: приватный черновик сотрудника не превращается в публичный черновик клиента после понижения доступа. При потере управленческой роли раздел истории переключается на обращения.

## Использование библиотек

Внешняя сессия и проекция подключены существующими адаптерами `useServiceSession`, `ServiceView`, `useCommandAction`, `useServiceAction`. Они используют публичные `wenay-common2/service/client` и `wenay-react2/react`: владение клиентом, подписка на store, готовность, команды, ожидание и ошибки.

Типы команд выводятся из `SupportDefinition`, тип проекции — из серверной функции `workspaceView`. Нет собственной транспортной, reconnect или схемной инфраструктуры. Клиент не импортирует серверную модель как runtime-модуль: её цепочка содержит `node:crypto`, поэтому все импорты модели — `import type`.

## Проверено

- `npm run typecheck --prefix apps/support` — проходит после финальных изменений интерфейса.
- `npm run build --prefix apps/support` — проходит. Сборщик сообщает о размере основного bundle около 524 КБ до gzip и текущей конфигурации Vite; это не ошибки сборки.
- Через отдельную вкладку CUA `http://127.0.0.1:3810/` выполнен вход владельца. После подключения отображаются реальная организация Northstar, два исходных обращения, приватная заметка, детали, срок ответа, вложения и доступный помощник.
- Визуально просмотрены экран входа и загруженный интерфейс владельца: панели, текст, состояние подключения и навигация отображаются без заметного наложения.

## Ограничение браузерной проверки

После ввода тестового текста первая попытка переключить «Только команде» завершилась таймаутом браузерного CDP. Последующие запросы актуального состояния тоже завершились таймаутом фокусировки. Сообщение не отправлялось.

Поэтому здесь **не заявлены** пройденными: отправка через браузер, полный цикл каждой роли, приглашение/публикация/восстановление через UI, импорт файла, мобильный viewport, отсутствие ошибок консоли. Проверки backend и репликации описываются отдельно и не подменяют эти действия.

Следующая проверка: восстановить доступ к локальной вкладке, выполнить клиентское обращение → приватную заметку специалиста → опубликованную статью руководителя → публичный ответ, проверить клиентскую видимость, затем макет 390 px и журнал браузера.
