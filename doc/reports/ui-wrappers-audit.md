## Модальные окна

Искали собственные реализации: `role="dialog"`, `aria-modal`, элемент `<dialog>` в коде приложений.

```text
grep -rn 'role="dialog"\|aria-modal\|<dialog' apps/*/frontend/*.tsx apps/*/organizer/*.tsx
```

**Собственных модальных окон в каталоге нет.** Все семь мест, где показывается модальное окно, используют публичный `Overlay` из `wenay-react2/ui`: approvals (подтверждение решения), content (замечания к версии), crm (сделки и карточка), forms (редактор и результаты), monitoring (форма проверки). Фокус, `Escape` и затемнение обеспечивает библиотека.

Единственный `<dialog>` в каталоге — в витрине `apps/catalog`, и он там уместен: это статическая страница без React и без зависимостей, `Overlay` туда не подключается сознательно.

Менять нечего.

## Async-обвязка

Искали собственные счётчики ожидания рядом с уже подключённым `useAsyncAction`.

| Место | Что найдено | Решение |
| --- | --- | --- |
| `apps/documents/frontend/studio.tsx` | `const [uploading, setUploading] = useState(false)` рядом с `useServiceAction` | **Оставлено.** `action.busy` показывает, что идёт команда; `uploading` показывает, что живёт многошаговая передача файла: `beginUpload` → чтение байтов → `upload`, с отменой на каждом шаге и обязательным `cancelUpload` в `finally`. Это не дубль ожидания, а состояние собственного протокола загрузки, которое переживает несколько вызовов внутри одного `action.action` |
| `apps/pizzeria/frontend/dish-photos.tsx` | `useState(false)` плюс свой `AbortController` | **Оставлено.** Компонент загружает фотографии прямым HTTP к authority, минуя команды сервиса: сжатие в canvas, ограничение размера, прерывание при размонтировании. `useAsyncAction` управляет вызовом команды и здесь неприменим; наружу состояние отдаётся через `onBusy`, то есть родитель всё равно блокируется одним признаком |
| `apps/pizzeria/frontend/catalog.tsx` | `useState(false)` | **Оставлено** по той же причине: он передаёт `onBusy` из `DishPhotos` в форму блюда |

Собственной обвязки, которая повторяла бы `useAsyncAction` над обычной командой сервиса, не найдено.

## Что это значит

Замечание контрольной точки было верным для CRM и там уже устранено. По остальному каталогу дублирования нет: React-поверхности библиотеки (`Overlay`, `useAsyncAction` через `useServiceAction`, `useServiceCommands` через `useCommandAction`) используются везде, где применимы, а три оставшихся собственных флага описывают многошаговую загрузку файлов — сценарий, которого публичные хуки не покрывают.

Задачи библиотеке отсюда не возникает: просить «хук многошаговой загрузки» по трём местам двух приложений преждевременно. Если такой сценарий появится в третьем продукте, это будет основанием вернуться.
